# 04 导航与代码结构 · 解答

> [!warning] 先做题再看
> 答案看一眼就记住了,但那是"知道",不是"会"。卡住 2 分钟再翻这里,
> 看完合上文档,回到题目重新做一遍。

> [!note] 本机环境速览(解答里都用这套)
> - LSP 键位:`gd` 定义 / `gr` 引用 / `K` 悬浮 / `<leader>rn` 重命名 / `<leader>ca` 代码操作 / `<leader>k` 诊断浮窗 / `[d` `]d` 诊断导航
> - 诊断列表:`<leader>fd`(telescope);Trouble 未绑 `<leader>xx`,要用就 `:Trouble diagnostics toggle`
> - gitsigns 无键位:blame/diff/hunk 跳转全部用命令(`:Gitsigns blame_line` 等);`<leader>gd` 是 DiffView,`<leader>gg` 是 lazygit
> - 练习文件都是 `.txt`,LSP / 注释 / 格式化相关操作先 `:set ft=python`(或对应类型)

## 题 61:跳转到匹配括号

**操作解法(按键)**:先 `f(` 把光标放到 `(` 上:

```
f(        行内查找:跳到下一个 (
%         跳到配对的右括号
%         再按一次,跳回左括号
```

f-string 里的 `{name}` 同样:光标放 `{` 上按 `%`,在 `{` / `}` 之间跳。

> [!note] `%` 的前提
> 光标必须落在括号字符上才生效。所以先 `f(` / `f)` / `f{` 定位到括号,再按 `%`。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `f(` | 行内查找,跳到下一个 `(`(找不到会蜂鸣) |
| `%` | 跳到配对的括号——前提是光标落在括号字符上 |
| `[(` / `])` | 跳到上一个/下一个**未配对**的 `(` / `)`(跨行找,嵌套括号用这个) |

| 命令 | 作用 |

| `Ctrl-o` | 沿跳转列表回退(回到刚才的调用处) |
| `Ctrl-i` | 沿跳转列表前进 |
| `:set ft=python` | 手动指定文件类型,触发 pyright 启动 |

## 题 63:跳转到下一个错误

**操作解法(按键)**:打开文件后先 `:set ft=python`(pyright 产生诊断):

```
]d               下一个诊断(跳到缺冒号那行)
]d               再下一个
[d               上一个
<leader>fd       telescope 诊断列表:列出全部诊断,回车跳到对应行
```

> [!note] 键位说明
> `]d` / `[d` 是 LSP 诊断导航键(你的配置已绑)。Trouble 没绑 `<leader>xx`,诊断列表用你已绑的 `<leader>fd`;想用 Trouble 就 `:Trouble diagnostics toggle`。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `]d` | 跳到下一个诊断(错误/警告),在最后一个诊断时循环回开头 |
| `[d` | 跳到上一个诊断 |
| `<leader>fd` | telescope 诊断列表(你已绑定),回车跳转 |
| `:set ft=python` | 练习文件是 `.txt`,手动指定 python 才有诊断 |

## 题 64:折叠函数

> [!warning] manual 模式下先造折叠
> 你的环境 `foldmethod=manual`(nvim 默认),文件打开时没有任何现成折叠——直接按 `zc` 会报 `E490: 找不到折叠`。必须先 `zf` 把折叠造出来,再收放。

**操作解法(按键)**:光标放函数体内任意一行(如 `line1`):

```
zfG        创建折叠:从光标行折到文件尾(函数体 6 行;def 行在光标上方,留在外面)
zc         关闭折叠(6 行收成 1 行)
zo         打开折叠
za         切换(z+a = toggle)
zM         全部折叠
zR         全部展开
```

不想折到文件尾的话,先 `V6jzf`(可视选中 6 行再折)也行。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `zfG` / `V6jzf` | manual 模式创建折叠(`zf` 是操作符,接移动或选区) |
| `zc` | close:关闭光标下的折叠 |
| `zo` | open:打开光标下的折叠 |
| `za` | 切换开/关 |
| `zM` / `zR` | 全部折叠 / 全部展开 |
| foldlevel | 默认 0,manual 模式没有自动折叠,平时看不到折叠线;`zf` 后才出现 |

## 题 65:折叠代码块

**操作解法(按键)**:

```
方法一:标记 + 范围折叠
ma           光标放 method2 行,打标记 a
mb           光标放 method3 的 pass 行,打标记 b
:'a,'bfold   折叠 a 到 b 之间的行(method2 ~ method3 含中间空行)

方法二:可视选中后折
V5jzf        选中 6 行(method2~method3)再折叠
```

> [!warning] 命令写法
> nvim 0.11 里 **`zf` 不是 Ex 命令**,`:'a,'bzf` 会报 `E492: 不是编辑器的命令`。带范围的折叠命令是 `:fold`(可缩写 `:fo`),所以是 `:'a,'bfold`。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `ma` / `mb` | 在光标位置打标记 a / b |
| `:'a,'bfold` | 以标记为范围创建折叠(`:fold` 是 `zf` 的 Ex 版本) |
| `zf` | 创建折叠(配合移动/可视选区,normal 操作符) |
| `V5jzf` | 可视选中 method2~method3 整块后折叠(超出文件尾会自动停) |

> [!warning] 其他环境的坑
> 如果 foldmethod 是 indent(LazyVim 等发行版默认),`zf` 会报 `E350`。你的环境默认 manual,不受影响。

## 题 66:折叠注释块

**操作解法(按键)**:光标放第一行 `"""` 上:

```
zf5j                  向下 6 行创建折叠(或 V5jzf)
:set foldlevel=0      所有折叠收起
:set foldlevel=3      展开到第 3 级(级别 ≤ 3 的折叠保持展开)
```

> docstring 全是顶格行,indent 折叠对它无效,所以先手动 `zf` 造出折叠,再体验 foldlevel 的"级别"控制。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `zf5j` | 从光标行起向下 6 行创建折叠 |
| `:set foldlevel=0` | 折叠级别 0:所有折叠(级别 ≥ 1)全部收起 |
| `:set foldlevel=3` | 折叠级别 3:级别 ≤ 3 的折叠保持展开 |
| foldlevel | 数字越小收得越狠;默认 0,手动折叠后用它控制展开深度 |

## 题 67:自动导入缺失模块

> [!note] 本质 LSP 题
> "自动补导入"是语言服务器的能力,按键没有直接对应物,靠 Code Action。

**操作解法(按键)**:打开文件后先 `:set ft=python`,光标放 `os` 上:

```
<leader>ca              Code Action 菜单(你已绑定)
选择 Auto-import / "Add import: os"   → 自动在文件顶部插入 import os
dd                      删掉顶部中文说明注释(可选,删完与目标一致)
```

**命令解法(手动保底,任何环境可用)**:

```
ggOimport os<Esc>o<Esc>   顶部上方插入 import os,再插一个空行
```

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `<leader>ca` | (LSP)打开 Code Action 快速修复菜单 |
| Auto-import | pyright 对"未导入的名字"提供自动导入修复 |
| `ggO` | 到文件头,在上方插入一行并进入插入模式 |
| `o` | 在当前行下方插入一行 |
| `dd` | 删除当前行 |

## 题 69:添加缺失的类型提示

> [!note] 本质命令题
> 逐段手工输入没有"一键"可言,`:s` 整行替换是最快的;按键法顺带练 `f`/`a` 移动与追加。

**命令解法(推荐,最快)**:光标放 `def add(a, b):` 一行上:

```
:s/def add(a, b):/def add(a: int, b: int) -> int:/
```

**操作解法(按键,练 f/a 移动)**:光标放行首:

```
0               回行首
f(              跳到左括号 (
l               进入参数区(光标到参数 a)
a: int<Esc>     在 a 后追加(a = append,光标后插入)
fb              跳到参数 b
a: int<Esc>     在 b 后追加
f)              跳到右括号
a -> int<Esc>   在 ) 后追加返回类型
```

> [!warning] 两个实测坑
> - `e` 会把 `(a,` 当做一个词:光标在 `(` 后按 `e` 会跳到逗号,追加到错位置。所以用 `l` 精确进到参数上。
> - `f)` 后光标停在 `)` 上,要按 `a` 追加 ` -> int`;按 `i` 会在 `)` **前面**插入,结果变成 `(b: int -> int)` 就错了。

> [!tip] 快速修复
> 部分 pyright 版本会提供 "Add type annotation" 快速修复,可以 `<leader>ca` 碰碰运气;没有就用上面的方法,一样快。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `:s/旧/新/` | 替换当前行(省略 `%` 就是当前行) |
| `f(` / `f)` / `fb` | 行内跳到下一个指定字符 |
| `a` / `i` | 光标后追加 / 光标前插入 |
| `0` | 跳到行首 |

## 题 70:查看当前行 Git blame

> [!warning] 先初始化仓库
> 教程目录默认不是 git 仓库,blame 没有数据。第 1 步只需做一次,第 2 步是每次必做。

**操作解法(按键+命令)**:gitsigns 没绑键位,blame 统一用原生命令:

```
" 1. 初始化仓库(整个教程目录,只做一次):
cd ~/nixos-config/notes/knowledge/nvim
git init && git add . && git commit -m "init"

" 2. 改一行再提交一次(blame 才有两笔提交可显示):
nvim 练习/070-查看当前行 Git blame.txt
:set ft=python
" 把 pass 改成 pass  # v1,然后 :w 保存:
:!git add . && git commit -m "v1"

" 3. 光标放改动的那行,查 blame:
:Gitsigns blame_line      当前行 blame:行下显示"提交哈希 · 作者 · 时间"
:Gitsigns blame           整个文件的 blame(预览窗)
```

> [!note] 键位说明
> 原题键位 `<leader>gb` 是旧版配置。你的配置里 gitsigns 没有绑定键位(只启用 gitsigns 本身),统一用 `:Gitsigns blame_line` / `:Gitsigns blame` 命令,一定可用。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `git init` | 把目录变成 git 仓库 |
| `git add . && git commit -m` | 暂存全部改动并提交 |
| `:Gitsigns blame_line` | 当前行 blame:行下显示"提交哈希 · 作者 · 时间" |
| `:Gitsigns blame` | 整个文件的 blame,预览窗展示 |

## 题 71:查看文件 Git diff

**操作解法(按键+命令)**:仓库已在题 70 初始化,改一行再对比:

```
nvim 练习/071-查看文件 Git diff.txt
:set ft=python
" 改一行:print("old") 改成 print("new"),保存 :w
:Gitsigns diffthis       与 HEAD 对比:左右分屏显示差异
:Gitsigns next_hunk      跳到下一个差异块
:Gitsigns prev_hunk      跳到上一个差异块
:diffoff!                退出所有窗格的 diff 模式
```

可选:`<leader>gd`(你的配置已绑定 DiffView)或 `:DiffviewOpen` 打开 diff 面板,更直观。

> [!note] 键位说明
> 原题 `:Gvdiff` 是 fugitive 的命令,你的配置没装 fugitive。gitsigns 没绑 `]h` / `[h` 键位,hunk 跳转用 `:Gitsigns next_hunk` / `:Gitsigns prev_hunk`。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `:Gitsigns diffthis` | 把当前文件与 HEAD 版本左右分屏对比 |
| `:Gitsigns next_hunk` / `prev_hunk` | 在差异块(hunk)之间跳转 |
| `:diffoff!` | 退出所有窗格的 diff 模式 |
| `<leader>gd` | 你的配置:DiffView(分屏对比) |
| `:DiffviewOpen` | diffview 插件(已装):打开 diff 面板 |

## 题 72:跳转到冲突位置

**操作解法(按键)**:文件里是模拟的合并冲突(`<<<<<<<` / `=======` / `>>>>>>>` 标记):

```
" —— 定位冲突位置 ——
/^<<<<<<<            搜索冲突起点(冲突标记都在行首)
:Gitsigns next_hunk  或:冲突块在 gitsigns 里就是一个 hunk,用命令跳

" —— 解决:保留 HEAD 版本(version_a)——
光标放 ======= 行:
V2jd                 删除 =======、version_b = 2、>>>>>>> branch 三行
ggdd                 回顶部,删掉 <<<<<<< HEAD

" —— 或者保留 branch 版本(version_b)——
光标放 <<<<<<< HEAD 行:
Vjd                  删除 <<<<<<< HEAD、version_a = 1 两行
dd                   删除 =======
jdd                  删除 >>>>>>> branch
```

> [!note] 键位说明
> 原题 `:GitConflictList` / `<leader>gc` 需要 git-conflict.nvim 插件(未装)。本练习用"搜索 + gitsigns hunk 命令"替代;gitsigns 没绑 `]h` / `[h` 键位,用 `:Gitsigns next_hunk` / `:Gitsigns prev_hunk`。

> [!tip] 真实冲突
> 真实冲突发生在 `git merge` 时。想体验完整流程:开个分支各改同一行、提交、合并产生冲突;解决后 `:Gitsigns stage_hunk` 暂存该块(或 `git add` 该文件),再 `git commit` 完成合并。lazygit(`<leader>gg`)里也能看到冲突文件。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `/^<<<<<<<` | 搜索冲突起点(冲突标记都在行首) |
| `:Gitsigns next_hunk` / `prev_hunk` | 下一个/上一个改动块(冲突块即 hunk) |
| `V2jd` | 选中 3 行删除(冲突的一版 + 两个标记) |
| `dd` | 删除当前行(单个标记行) |
| `ggdd` | 回文件头删一行 |
| `:Gitsigns stage_hunk` | 暂存当前 hunk(解决冲突后标记"已解决") |

## 题 73:水平分屏比较

> [!note] 本质命令题
> 分屏和 diff 都是 Ex 命令的领域,没有按键对应物。

**操作解法(按键+命令)**:先准备一个副本(用题 71 的练习文件做实验):

```bash
cd ~/nixos-config/notes/knowledge/nvim/04-导航与代码结构
cp "练习/071-查看文件 Git diff.txt" /tmp/071-副本.txt
```

```vim
nvim 练习/071-查看文件 Git diff.txt
:set ft=python
:diffsplit /tmp/071-副本.txt   " 水平分屏并进入 diff 模式
" 在任意窗格改一行(如 old → new),差异立即高亮
:diffoff                       " 退出 diff 模式
Ctrl-w q                     " 关闭当前窗格
```

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `:diffsplit 文件` | 水平分屏打开文件并进入 diff 模式 |
| `:vert diffsplit 文件` | 垂直版分屏 diff |
| `:diffoff` | 退出当前窗格的 diff 模式 |
| `Ctrl-w q` | 关闭当前窗格(你的配置未绑 LazyVim 的 `<leader>wd`) |
| `Ctrl-w s` | 原生水平分屏(不开 diff) |

## 题 75:在分屏间移动内容

## 题 76:SQL 查询格式化

> [!note] 本质命令题
> 拆行/加空格全是替换的活,按键没有对应物。以下为纯 nvim 命令序列,实测可达目标。

**命令解法**:

```
:%s/^SELECT /SELECT\r/    SELECT 后换行
:%s/,/,\r/g               逗号后换行
:%s/ FROM /\rFROM /       FROM 前换行
:%s/ WHERE /\rWHERE /     WHERE 前换行
:%s/ AND /\r  AND /       AND 前换行,并缩进 2 格
:%s/>/ > /                > 两侧加空格
:%s/=/ = /                = 两侧加空格
:2,4>>                    第 2-4 行(列名)右缩进 2 次,共 4 格
```

> [!tip] 关于格式化器
> conform 没配 SQL 格式化器(sqlfluff/sqlformat 均未装),`:set ft=sql` 后按 `<leader>cf` 没有对应动作。上面这条手工序列保证可达目标,不用装任何东西。

**关键命令解析**:

| 部分 | 作用 |
|---|---|
| `\r` | 替换内容里的换行符(核心技巧) |
| `:%s/^SELECT /SELECT\r/` | 在 SELECT 后换行(`^` 锚定行首) |
| `:%s/,/,\r/g` | 每个逗号后换行 |
| `:%s/ FROM /\rFROM /` | 关键词前换行(带两侧空格防止误伤) |
| `:2,4>>` | 第 2-4 行右缩进 2 次(每次一个 shiftwidth,你的配置是 2 格) |

## 题 77:SQL 关键字大写

**操作解法(按键)**:光标放 `select` 上(行首):

```
gUiw          select → SELECT(光标在词上任意位置即可)
ww            连跳两词:* → from
gUiw          from → FROM
ww            连跳两词:users → where
gUiw          where → WHERE
```

**命令解法(推荐,一次搞定)**:`:s` 加 very magic 正则:

```
:%s/\v<(select|from|where)>/\U\1/g
```

> [!warning] 外部命令依赖
> 教程里的 `:%!sqlformat -k upper`(整文件过滤)需要外部命令 sqlformat——本机未装,此方法跳过,上面两种方法已够用。

**关键命令解析**:

| 部分 | 作用 |
|---|---|
| `gUiw` | 把光标所在词转大写(词内任意位置) |
| `w` | 跳到下一个词 |
| `\v` | very magic:让 `(` `)` `\|` 直接有正则含义,不用再转义 |
| `<(select\|from\|where)>` | `<>` 是词边界,里面是三个关键字任选其一 |
| `\U\1` | 替换时把捕获组 1 转成大写 |

## 题 79:多行转数组

> [!note] 本质命令题
> 合并行靠 `J` 系列操作符。练习文件初始是单行,先按题 78 的方法拆成多行再合并。

**操作解法(按键+命令)**:先把文件拆成题 78 的样子(输入状态):

```
const arr = [
  1,
  2,
  3
];
```

再合并:

```
:%s/^\s\+//        去掉所有行首缩进(不然合并会残留缩进)
gg                  回第 1 行
gJ                  合并下一行,不加空格([ 与 1 之间)
J                   合并下一行,加一个空格(1 与 2 之间)
J                   再合并一行(2 与 3 之间)
gJ                  最后一行不加空格(3 与 ]; 之间)
```

**命令解法**:连写就是 `gggJJJgJ`——`gg` 回行首,然后 `gJ`、`J`、`J`、`gJ` 依次合并 5 行。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `:%s/^\s\+//` | 去掉每行行首空白 |
| `gJ` | 合并下一行,不加空格(处理 `[` 与 `];`) |
| `J` | 合并下一行,加一个空格(处理元素之间) |
| `gggJJJgJ` | `gg` 回行首,然后 gJ、J、J、gJ 依次合并 5 行 |

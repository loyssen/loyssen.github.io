## 题 101:综合练习重构代码

### 阶段 1:通读与规划

**操作解法(按键)**:

```
:set number    显示行号,看清嵌套层级(取消用 :set nonumber)
gg             回到文件头,从头开始读
%              在配对的 ( ) 之间跳转,理清嵌套
}              跳到下一段(空行分隔的代码块)
```

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `:set number` | 显示行号,嵌套结构一目了然 |
| `%` | 跳转到配对括号(光标放在 `(` 或 `)` 上) |
| `}` | 跳到下一段 |
| `gg` | 跳到文件第一行 |

**自检方法**:不看代码,把函数行为说成一句话——"从 `x` 开始逐层检查,遇到非正数就停止并返回已累加的部分;三个数都为正返回 `x+y+z`;`x` 非正则返回 0"。能说清楚 = 读懂了。4 个分支的返回值:

| 条件 | 返回值 |
|---|---|
| `x>0, y>0, z>0` | `x+y+z` |
| `x>0, y>0, z<=0` | `x+y` |
| `x>0, y<=0` | `x` |
| `x<=0` | `0` |

### 阶段 2:修复缩进

> [!warning] 先做这一步
> 练习文件是 `.txt`,不先设置文件类型的话,nvim 不知道这是 Python,
> 自动缩进和语法检查都不会生效。打开文件后先执行:
> ```
> :set ft=python
> ```
> 缩进宽度按 4 空格(配置默认一般就是 4,可用 `:set sw?` 查看)。

**操作解法**:

1. **先试全文件自动重排**:`gg=G`。

   > [!warning] 实测:gg=G 修不好错位 else
   > 自动重排只处理"该往右缩进的层",对"该往左退格的 `else`"经常无能为力。
   > 实测两种结果(取决于你的 nvim 配置):
   > - 内置 Python 缩进:`if` 行对齐到了 4/8/12 层,但错位的 `else:` 行被原样保留;
   > - treesitter 缩进:整个嵌套被"打平",全部顶格或只缩 4 空格。
   > 无论哪种,此时语法检查都会报 `IndentationError`——正好用它当"探针":
   > 报错 = 还没修好,不报错 = 缩进已合法。
   > 工具不是万能的,这正是要手动补的地方。

2. **修复错位的 `else:`**,两种方法,推荐组合使用:
   - **`>>` / `<<` 微调法**:每次移动一个 `shiftwidth`(4 空格),`<<` 往左退、`>>` 往右进,配合 `.` 重复。把 `else:` 调到与配对的 `if` 同一列,把 `return` 调到 else 块内一层。
   - **`dd` + `o` 重输法**:删掉错位行,`o` 新开一行重新输入 `else:`。输入冒号时 nvim 会重新计算缩进——但注意:它按"上一行缩进"推断,**只有上一行已经正确时才对齐得准**(上一行也错位的话,重算结果照样错位)。所以重输后仍要配合 `>>` / `<<` 校正。
   - 每修好一处,用 `==` 重排当前行确认没有副作用。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `gg=G` | 从文件头到文件尾按语法自动重排缩进 |
| `>>` / `<<` | 当前行右移 / 左移一个 `shiftwidth`(4 空格) |
| `.` | 重复上一次修改(连续微调同一行) |
| `dd` + `o` | 删行重输,让 nvim 重新计算缩进 |
| `==` | 按语法重排当前行 |

**自检方法**:

```vim
:!python3 -m py_compile %
```

`%` 会展开成当前文件名;没有任何输出 = 语法合法;报 `IndentationError`(消息形如 `unindent does not match ...` 或 `expected an indented block ...`)= 还有错位。再肉眼检查:3 个 `else:` 分别与 `if x>0:` / `if y>0:` / `if z>0:` 对齐。用 `u` 撤销后重做一遍。

### 阶段 3:重命名函数

**操作解法(命令)**:

```vim
:%s/\<f\>/calculate_sum/g
```

**关键命令解析**:

| 部分 | 作用 |
|---|---|
| `%` | 全文件范围 |
| `\<` | 词首边界:只匹配"词开头"的 `f`,不会命中 `foo`、`f1` 里的 f |
| `\>` | 词尾边界 |
| `g` | 每行所有匹配都替换 |

**自检方法**:

```vim
:%s/\<f\>//gn
```

这是"只计数不替换"(`n` = 报告匹配数)。替换干净后应显示 `E486: 找不到模式`——这就是"一个都不剩"的意思;如果显示 `N match`,说明还有漏网的独立 `f`。

> [!warning] 别用 /f\> 验证残留
> 表面看 `f\>` 是"词尾的 f",但 `def` 末尾的 f 也满足词尾条件,
> 搜索会"找到"它,造成误报。验证残留用上面的计数命令(带 `\<`),不用搜索。

**自检**:

- 第一行变成 `def calculate_sum(x,y,z):`
- `:%s/\<f\>//gn` 报 `E486: 找不到模式`
- 能说出 `\<` 和 `\>` 的作用(词边界,防止误替换)

### 阶段 4:重构嵌套 if 为提前返回

> [!note] 本质是思路题
> 按键层面就是删行、新开行、改词,难点在"改成什么样":
> 嵌套 if 的 else 分支,本质是"条件不满足时立即返回"。

**操作解法**:

把 3 个 else 分支分别"取反、上移"成前置守卫,最后留兜底:

| 原 else 分支 | 取反条件 | 守卫形态 |
|---|---|---|
| `x<=0` 时返回 0(最外层) | `x <= 0` | `if x <= 0: return 0` |
| `x>0 且 y<=0` 时返回 x | `y <= 0` | `if y <= 0: return x` |
| `x>0, y>0 且 z<=0` 时返回 x+y | `z <= 0` | `if z <= 0: return x + y` |
| 全部通过 | —— | `return x + y + z`(兜底) |

操作手法:`dd` 删掉 `else:` 行和它的 `return`,`o` 在正确层级新开行输入守卫;`>>` / `<<` 调缩进;`ciw` 改词、`cw` 改行内内容。守卫写成两行还是一行用 `J` 合并,形式自由,逻辑正确即可。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `dd` / `o` | 删行 / 下方新开行 |
| `J` | 合并下一行到当前行尾 |
| `ciw` | 修改整个词(文本对象,01 章学过) |
| `>>` / `<<` | 调缩进 |

**为什么提前返回是等价的**:原代码"如果 x 非正就返回 0,否则继续" = "先判断 `x<=0`,满足就返回 0,不满足才走到下面"。条件取反之后,嵌套的层级就变成了顺序的守卫,每个守卫只"拦截"一种情况。

**自检方法**(语义测试,4 个分支全覆盖):

```vim
:!python3 -c "exec(open('练习/101-综合练习.txt').read()); print(calculate_sum(1,2,3), calculate_sum(-1,9,9), calculate_sum(5,-1,9), calculate_sum(5,5,-1))"
```

必须输出 `6 0 5 10`,一个数字都不能差(4 个测试分别是全正 / x 非正 / y 非正 / z 非正)。再跑一遍 `py_compile` 确认语法没有写坏。

### 阶段 5:添加类型注解和 docstring

**操作解法**:

1. **参数注解**:光标放参数列表内,`ci(` 一次性改掉整个括号内容(01 章的文本对象),重新输入:
   ```
   x: int, y: int, z: int
   ```
   或者 `a` / `i` 逐个在参数后插入 `: int`。
2. **返回注解**:光标放 `)` 上按 `a` 追加 ` -> int`,整行变成:
   ```
   def calculate_sum(x: int, y: int, z: int) -> int:
   ```
3. **docstring**:在 `def` 行下方 `o` 新开一行,输入三引号(不自动补全就手动补上右引号)。
4. **格式**(Google 风格):一行摘要 → 空行 → `Args:` 每参数一行 → 空行 → `Returns:` 一行。docstring 里参数行的对齐**手动补空格即可**(实测:docstring 属于字符串,自动缩进对字符串行一律不动,别指望它帮你对齐)。
5. 写完 `gg=G` 重排一遍,确认没把结构弄坏。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `ci(` | 修改括号内内容(文本对象) |
| `a` / `i` | 光标后 / 前插入 |
| `o` / `O` | 下方 / 上方新开行 |

**自检方法**:

- `py_compile` 无报错;参数注解、返回注解齐全;docstring 有摘要、Args、Returns 三部分,Args 参数行对齐。
- 实测点:把 `x: int` 故意改成 `x: str`,再跑 `py_compile`——**依然通过**。类型注解只是给人(和工具)看的提示,不影响运行。确认这个事实后 `u` 撤销回来。

**操作解法**(diff 对比):

```vim
:new            新开一个空窗口
:set ft=python  新窗口也要设置文件类型
" 在空窗口里粘贴下方目标代码
:diffthis       两个窗口各执行一次,进入 diff 对比模式
]c              跳到下一处差异
[c              跳到上一处差异
:diffoff        退出对比
dd              删掉对照窗口
<C-w>w          切回你的作品窗口
```

**目标代码**(重构完成后的完整代码):

```python
def calculate_sum(x: int, y: int, z: int) -> int:
    """
    Calculate the sum of positive numbers.

    Args:
        x: First number
        y: Second number
        z: Third number

    Returns:
        Sum of positive numbers
    """
    if x <= 0:
        return 0

    if y <= 0:
        return x

    if z <= 0:
        return x + y

    return x + y + z
```

**逐项对照**:

- 函数名、参数名与目标一致(`calculate_sum`,参数仍叫 `x/y/z`,不要顺手改名)
- 缩进:4 空格层级,无 Tab
- 结构:3 个提前返回守卫 + 1 个兜底 `return`,没有嵌套 `if`
- 类型注解与 docstring 与目标一致

**最终验收**(行为必须完全一致):

```vim

```

输出必须仍是 `6 0 5 10`。

# 7.3 文档处理与切分

> Chunking 是 RAG 系统中最被低估、但影响最大的环节。

---

## 为什么 Chunking 如此重要

```mermaid

    TOO_SMALL["❌ Chunk 太小<br/>缺少上下文<br/>检索碎片化"]
    JUST_RIGHT["✅ Chunk 适中<br/>完整语义单元<br/>上下文充足"]
    TOO_LARGE["❌ Chunk 太大<br/>检索不精准<br/>包含噪声"]
```

## Chunking 策略

### 1. 固定大小切分

```python
text = "这是一段很长的文本..."

# 最简单：固定 512 tokens，重叠 50 tokens
chunks = []
chunk_size = 512
overlap = 50

for i in range(0, len(tokens), chunk_size - overlap):
    chunk = tokens[i:i + chunk_size]
    chunks.append(chunk)
```

| 优点 | 缺点 |
|------|------|
| 简单、计算快 | 可能切在句子中间 |
| 可预测大小 | 破坏语义完整性 |

### 2. 基于句子的切分

按自然段落/句子边界切分，保持语义完整：

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=512,
    chunk_overlap=50,
    separators=["\n\n", "\n", "。", ".", "！", "？", " ", ""]
)

chunks = splitter.split_text(document)
```

### 3. 语义切分（Semantic Chunking）

> 用 Embedding 判断句子间的语义相似度，在「语义边界」处切分。

```python
# 计算相邻句子 Embedding 的余弦相似度
# 如果相似度骤降 → 说明话题切换 → 在这里切
sentence_embeddings = model.encode(sentences)
similarities = cosine_similarity(sentence_embeddings[:-1], sentence_embeddings[1:])

# 在低相似度处切分
breakpoints = [i for i, sim in enumerate(similarities) if sim < threshold]
```

## Chunking 经验法则

| 数据类型 | 推荐 Chunk 大小 | 重叠 |
|---------|----------------|------|
| 技术文档 | 512-1024 tokens | 10-15% |
| 对话记录 | 256-512 tokens | 20% |
| 学术论文 | 1024-2048 tokens | 10% |
| FAQ | 完整条目 | 0 |
| 代码 | 按函数/类 | 0 |

## 文档元数据的重要性

```python
chunk = {
    "text": "机器学习是人工智能的一个分支...",
    "metadata": {
        "source": "ml_handbook.pdf",
        "page": 42,
        "chapter": "监督学习",
        "title": "机器学习基础",
        "chunk_index": 5,
        "total_chunks": 20,
    }
}
```

元数据让你能：
- 标注引用来源给用户看
- 按章节/类型过滤检索
- 追踪和调试检索质量

## 高级策略

| 策略 | 说明 |
|------|------|
| **Small-to-Big** | 检索用小 Chunk，生成用大 Chunk（包含上下文） |
| **多粒度索引** | 同时索引摘要 + 详细内容 |
| **句子窗口** | 检索到目标句子后，扩展前后 N 句 |
| **层级索引** | 文档 → 章节 → 段落 → 句子，逐层检索 |
| **假设性问题** | 用 LLM 为每个 Chunk 生成可能的问题，用问题做索引 |

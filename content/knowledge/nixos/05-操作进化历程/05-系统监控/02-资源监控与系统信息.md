# 资源监控与系统信息:free/df/du → btop/glances;neofetch → fastfetch

> [!info] 本页内容
> 内存、磁盘、负载——分别怎么查?有没有"一条命令全看全"?
> neofetch 为什么死了,fastfetch 凭什么接班。

## 一、单项查询:free / df / du(1971 系老祖宗)

| 命令 | 问什么 | 现代用法 |
|---|---|---|
| **free** | 内存还剩多少 | `free -h`(人类可读单位) |
| **df** | 磁盘分区还剩多少 | `df -h`(看所有挂载点) |
| **du** | 目录/文件占多少 | `du -sh 目录`(汇总一个目录) |

df/du 和 ps 一样出生于 1971 年的 Unix V1;free 来自 BSD 传统,后并入 procps。哲学是**问一个数、给一个数**——50 多年过去仍是最高频查询:

```
free -h              # 内存:total/used/available 一行看懂
du -sh ~/.cache      # 目录占用(排查"谁把磁盘吃满了")
```

## 二、系统级统计:iostat / vmstat(1980 年代)

BSD 时代的"系统体检"工具,至今在役:

```
vmstat 1             # 每秒刷新:CPU 占用、内存换页、IO 等待
iostat 1             # 每秒刷新:每个磁盘的读写速率
```

- **vmstat**:虚拟内存统计——看整体 CPU/内存压力;数字表格、适合脚本,但可读性差
- **iostat**:磁盘 IO 统计——定位"磁盘是不是瓶颈";现代发行版由 sysstat 套件提供

## 三、聚合工具:从"单个数"到"整机仪表盘"

1970-80 年代的工具都是一问一答,2010 年代起出现**聚合监控工具**,一个界面看全部资源:

| 工具 | 年份 | 语言 | 定位 |
|---|---|---|---|
| **btop** | 2021 | C++ | 桌面仪表盘(上篇主角,CPU/内存/磁盘/网络一屏) |
| **glances** | 2014 | Python | 服务器/多机监控:Web 界面、REST API、插件 |
| **btm**(bottom) | 2019 | Rust | btop 的 Rust 派对手,轻量终端向 |

### glances 详解(服务器场景)

```
glances              # 本机全资源一屏;glances -w 起 Web 界面浏览器看
```

| 特性 | 说明 |
|---|---|
| 覆盖 | CPU/内存/磁盘/网络/进程/温度全在,可加容器/GPU 插件 |
| 远程/输出 | 多台机器接入集中看;TUI/Web/CSV/JSON 可接监控系统 |

**btm(bottom)**:Rust 写的聚合监控,风格介于 htop 和 btop 之间——下半区图表、上半区进程;零配置 + 极省资源,轻量服务器比 btop 更合适。

## 四、对比表:三个聚合工具

| | btop | glances | btm |
|---|---|---|---|
| 语言 | C++ | Python | Rust |
| 场景 | 个人桌面 | 服务器/多机 | 轻量终端 |
| 图表 | 曲线+条,GPU 监控 | 文本+条形 | 字符图 |
| 远程监控 | 无 | ✅(Web/API) | 无 |
| 已装? | ✅ 你已装 | 未装 | 未装 |

> [!note] btop 已覆盖日常聚合需求
> 你已经装了 btop,CPU/内存/磁盘/网络一屏全有——glances 和 btm 是"换一种用法"的备选,不是必需品。

## 五、系统信息工具:neofetch(2015)→ fastfetch(2021)

终端截图里"发行版 Logo + 系统信息"的艺术,来自 **neofetch**(2015 年 Dylan Araps 用 bash 写的):`neofetch` 打印 Logo + 内核/桌面/CPU/内存/主题。

但它本质是**静态陈列**——信息没有实时价值,更像"桌面宣言"。2024 年 4 月项目正式归档,社区迅速转向继任者:

| | neofetch | fastfetch |
|---|---|---|
| 语言 | bash | C |
| 速度 | 秒级 | 毫秒级 |
| 显示 | 文本 Logo | 文本/图片(Kitty 协议)、多种 Logo 风格 |
| 维护 | 2024 归档 ❌ | **现役主力** ✅ |

**fastfetch 你已装**:`fastfetch` 一条命令即可,图片/纯文本都支持。

> [!tip] 装逼工具的价值
> fastfetch/neofetch 没"用"却活着:终端截图文化让它们成为 Linux 身份标识。你的 packages.nix 已装 fastfetch + neofetch(怀旧),日常用 `fastfetch` 即可。

## 六、排障最后一步:日志

资源看着正常但服务就是不行?查日志——`journalctl`(systemd 日志中心)的完整用法见 [[01-Linux基础/06-进程与systemd服务]] 第 5 节,这里不重复。

## 七、现今流行情况

- **neofetch 已死,fastfetch 成为新截图标准**(2024 年后新教程截图基本是它)
- **btop** 是个人桌面最热的整机监控;服务器上 htop 仍占大头,glances 在自托管/多机场景流行
- 聚合工具持续内卷(btm/gtop/nvtop……),都以 btop 为标杆互相抄;单项工具(free/df/du)地位永恒

## 八、怎么选(你的环境)

| 场景 | 命令 |
|---|---|
| 内存还剩多少 | `free -h` |
| 磁盘空间 | `df -h` / `du -sh 目录` |
| 整体看一眼 | `btop`(已装) |
| 怀疑磁盘 IO 瓶颈 | `iostat 1`(需 sysstat) |
| 多台服务器集中监控 | glances(需要时再装) |
| 截图/装逼/记录配置 | `fastfetch`(已装) |
| 服务出问题 | 排障套路,见上节链接 |

> [!tip] 监控决策树
> 单项问题用单项工具(free/df/du),整体观察用 btop,深挖用 vmstat/iostat,查日志看 systemd——**从粗到细,一层层套**。

> [!tip] 记忆法
> free/df/du 问"还有多少",btop 看"正在干什么",fastfetch 负责"我是什么机器"。

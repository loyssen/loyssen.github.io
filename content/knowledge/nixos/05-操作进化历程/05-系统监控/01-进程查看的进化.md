# 进程查看的进化:ps → top → htop → btop

> [!info] 本页内容
> top 统治了 20 年,为什么还有 htop/btop?
> Linux 的"任务管理器"是哪一代?进程怎么找、怎么杀。

## 一、进程是什么(30 秒)

运行中的程序叫**进程**:程序是硬盘上的文件,进程是它被加载进内存、正在执行的实例,内核给它一个编号 **PID**——所有管理都围绕 PID 展开。

- `fork`(复制)+ `exec`(替换成新程序)产生进程;`/proc`(1988 年 SVR4 引入)把每个进程暴露成目录
- 看进程 = 读 /proc(ps/top 的原材料);管进程 = 发信号(kill)

## 二、谱系时间线

```
ps(1971) → top(1984) → htop(2004) → btop(2021)
静态快照     动态刷新      彩色交互     图表仪表盘
```

| 代际 | 年份 | 定位 |
|---|---|---|
| **ps** | 1971 | Unix V1 里就有,进程快照,输出即打印 |
| **top** | 1984 | 第一代"动态刷新"查看器,每秒更新 |
| **htop** | 2004 | ncurses 全屏交互:颜色、进程树、F 键操作 |
| **btop** | 2021 | C++ 重写,GPU/图表/net,现代仪表盘 |

## 三、ps:静态快照(1971)

`ps` 一次性输出,**适合脚本和管道**;持续观察交给 top:

```
ps aux                ← 全部进程 + 详细列(BSD 风格,最常用)
ps -ef                ← 另一种风格,多一列 PPID(父进程)
ps aux | rg nvim      ← 找某个程序(管道配合 rg)
```

## 四、top:第一代动态刷新(1984)

1984 年 William LeFebvre 写的 top,解决 ps 的痛点——**不刷新就没法"盯"**:

```
top                   ← 全屏,每 3 秒刷新,默认按 CPU 占用排序
```

- 上半屏系统概况、下半屏进程列表;`q` 退出、`k` 杀进程、`M` 内存排、`P` CPU 排;只占几十 KB,老服务器上的永恒标准

## 五、htop:彩色交互时代(2004)

2004 年 Hisham Muhammad 用 ncurses 重做 top,界面从"表格"变成"仪表盘":

| 特性 | 说明 |
|---|---|
| 配色 | CPU/内存条带颜色,压力一眼可见 |
| 进程树+操作 | `F5` 树状;`F4` 过滤、`F6` 排序、`F9` 杀;光标选进程不背 PID,列表可滚动 |

**htop 的意义**:把"看进程"从读数字变成操作界面——这一步被 btop 继承并放大。

## 六、btop:图表仪表盘(2021,你已装、日常用)

2021 年 btop 把 Python 时代的 bashtop/bpytop 合并重写为 C++,不只是进程查看器,而是**整机监控台**:

```
btop                  ← 打开
```

| 模块 | 显示内容 |
|---|---|
| CPU / MEM | 每核占用曲线;内存/交换实时条 |
| DISK / NET | 磁盘读写速率;每个网卡上传/下载实时图 |
| PROC | 进程列表(可排序/树状) |

**常用按键**:`t` 进程树、`f` 过滤、`k` 杀选中进程、`Enter` 检视、`p` 暂停、`↑↓` 移动。杀手锏是 GPU 监控、自定义布局与主题、鼠标操作——你的 packages.nix 已装,日常 `btop` 就是任务管理器。

## 七、对比表

| | ps | top | htop | btop |
|---|---|---|---|---|
| 年份 | 1971 | 1984 | 2004 | 2021 |
| 形态 | 一次性输出 | 全屏刷新 | 全屏交互 | 仪表盘 |
| 进程树 | 无 | 无 | ✅ | ✅ |
| 图表 | 无 | 无 | 条形 | 曲线+条 |
| 资源占用 | 无 | 极小 | 小 | 中 |
| 现状 | 脚本用 | 老服务器 | **服务器标配** | **桌面新贵** |

## 八、现今流行情况

- **htop** 仍是默认安装量最大的交互监控器——SSH 进任何机器都有它
- **btop** 2021 年后在个人桌面快速普及;Rust 派 **btm**(bottom)是同期竞争者
- **top** 没人主动装,但老系统里永远在;**ps** 是脚本和排查的底层 API,`ps aux | rg xxx` 最高频

## 九、怎么选(你的环境)

| 场景 | 用 |
|---|---|
| 一次查询/写脚本 | `ps aux | rg 名字` |
| 日常整机监控 | **btop**(已装,一屏全有) |
| SSH 到服务器 | htop(哪台机器都有) |

**杀进程最短路径**:

```
pgrep -af nvim        ← 先看会匹配到什么(避免误杀)
kill PID              ← SIGTERM(15),礼貌退出,可存盘
kill -9 PID           ← SIGKILL(9),强杀,最后手段
pkill -x nvim         ← 按精确进程名杀
```

> [!tip] 注意 `pkill -f`
> `pkill -f xxx` 匹配完整命令行——自己命令行里含 xxx 会误杀自己,先 `pgrep -af` 确认。

> [!tip] 记忆法
> ps 拍照,top 盯梢,htop 操作,btop 仪表盘——一代比一代更像"任务管理器"。
> 日常 90% 的监控用 btop 就够;ps 是唯一必须记住的"底层 API"。

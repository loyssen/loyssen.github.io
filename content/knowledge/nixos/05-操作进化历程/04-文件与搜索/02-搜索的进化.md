# 搜索的进化:grep → ripgrep / find → fd

> [!info] 本页内容
> grep 统治了 40 年,为什么被 ripgrep 挑战?
> `find` 和 `fd` 差在哪?现代搜索工具为什么是 Rust 的天下。

## 一、内容搜索:grep(1973)→ ack → ag → ripgrep

### grep 的诞生(1973)
Ken Thompson 一夜写出的工具,名字来自 ed 编辑器的命令 `g/regular expression/p`(全局匹配正则并打印)。40 年统治:

```
grep -r "TODO" src/     ← 递归搜索
grep "error" log.txt    ← 单文件过滤
```

**grep 的问题**(现代眼光):

- 慢:逐个文件扫,无并行,无忽略规则
- 无默认忽略:搜代码会翻进 `node_modules`、`.git`
- 输出朴素:无颜色(要靠参数)、无上下文分组

### 三代挑战者

| 工具 | 年份 | 语言 | 贡献 | 结局 |
|---|---|---|---|---|
| **ack** | 2005 | Perl | 默认尊重 .gitignore、上下文输出 | 被更快者取代 |
| **ag** (the_silver_searcher) | 2012 | C | 并行搜索,快 5-10 倍 | 维护停滞 |
| **ripgrep (rg)** | 2016 | Rust | 快(比 ag 再快数倍)+ 默认忽略 + 零配置 | **现役标准** |

### ripgrep 为什么赢

| 特性 | 说明 |
|---|---|
| 速度 | 并行 + 内存映射,超大仓库秒级 |
| 默认忽略 | 自动跳过 .gitignore / 二进制 / 隐藏文件——**不用记参数** |
| 正确性 | 正则引擎无回溯陷阱,复杂模式不卡死 |
| 输出 | 颜色、上下文、JSON 输出 |
| 嵌入 | VS Code 的搜索后端就是 rg;telescope 的 live_grep 也用 rg |

```
rg "TODO" ~/nixos-config       ← 一键搜整个配置仓库
rg -i "nvidia" modules/        ← 忽略大小写
rg "fn\(" --type rust          ← 按语言类型过滤
```

> [!tip] 记忆:rg 就是"不用想参数的 grep"
> 你在 nvim 里按 `<leader>fg`(全局搜索),背后跑的就是 rg——教程里 `:vimgrep` 是原生的,日常用 `<leader>fg` 更快。

## 二、文件名搜索:find(1979)→ fd(2018)

### find:功能全但难记

```
find . -name "*.md" -type f          ← 找文件
find . -mtime -7                     ← 7 天内修改
```

问题:参数风格怪异(`-name` 要放最后、默认递归、无忽略规则)。

### fd:好记的 find

| | find | fd |
|---|---|---|
| 语法 | `find . -name "*.md"` | `fd "\.md$"`(正则直接搜) |
| 默认 | 递归 + 全部 | 尊重 .gitignore、跳过隐藏 |
| 彩色 | 无 | ✅ |
| 组合 | 复杂 | `fd -e md`(按扩展名)、`fd -t d`(只看目录)、`fd -d 3`(限深度) |

```
fd -e nix            ← 找所有 .nix 文件(你的配置仓库神器)
fd -t d              ← 只找目录
fd "config" -x bat   ← 找到的每个文件执行 bat(-x 执行)
```

## 三、为什么都是 Rust

2015 年后"重写经典"运动的主力几乎全是 Rust:

- **性能**:无 GC、内存可控,搜索类工具榨干硬件
- **安全**:内存安全,不会有 C 工具的越界 bug
- **生态**:cargo 让"写一个更快的小工具"成本极低——rg/fd/bat/lsd 全是个人项目成长起来的

## 四、组合:搜索是管道的输入源

```
fd -e md | fzf | xargs bat     ← 模糊选文件 → 看内容
rg -l "TODO" | xargs nvim      ← 列出含 TODO 的文件 → 全打开
```

搜索工具是"现代管道"的起点——下一节《模糊查找与目录跳转》接上 fzf/zoxide 完成闭环。

# Rust 的诞生与核心设计

> [!info] 本页内容
> Rust 从哪来?"所有权"到底是什么?为什么它敢承诺"安全 + 性能兼得"?
> 和 C/Go 比,Rust 的取舍是什么。

## 一、诞生背景

| 时间 | 事件 |
|---|---|
| 2006 | Mozilla 工程师 Graydon Hoare 的个人项目(讨厌电梯等他,研究期开发) |
| 2010 | Mozilla 正式赞助,定位:Firefox 内核(Gecko)的接班人语言 |
| 2015 | **1.0 发布**——"安全系统编程"正式登场 |
| 2021 | Rust 基金会成立(微软/谷歌/AWS 等加入,行业背书) |
| 2026 | TIOBE 前 15,系统级语言中增长最快 |

**痛点驱动**:Firefox 的 C++ 代码库常年被内存 bug 困扰(浏览器是漏洞重灾区)。
Rust 的答案:**让编译器在编译期就证明代码没有内存错误**,而不是靠运行时检查或程序员自觉。

## 二、核心机制:所有权(Ownership)

这是 Rust 与所有其他语言的分水岭,也是学习曲线最陡的地方。

### 问题:内存谁来管?

| 语言 | 内存管理 | 代价 |
|---|---|---|
| C/C++ | 程序员手动分配/释放 | 漏释放(泄漏)、重复释放(崩溃)、悬垂指针(漏洞) |
| Java/Go/Python | 垃圾回收(GC)自动回收 | 运行时开销、暂停、不可控 |
| **Rust** | **编译器在编译期静态分析** | 无运行时开销、无漏洞——但学习曲线陡 |

### 三条规则(编译期强制)

```
1. 每个值有唯一"所有者"(owner)
2. 值可以"借用"(borrow),但同一时刻要么多个只读借用,要么一个可变借用
3. 所有者离开作用域,值自动释放
```

```rust
fn main() {
    let s = String::from("hello");   // s 拥有这块内存
    let t = s;                        // 所有权移交给 t,s 失效(编译报错!)
    // println!("{}", s);             // ← 这行编译不过:"use after move"
}
```

**效果**:缓冲区溢出、悬垂指针、数据竞争这些"C 语言的天灾",在 Rust 里**编译期就被拒绝**——不是"小心别写错",而是"根本写不出来"。

> [!note] 一句话理解
> C 信任程序员,GC 语言信任运行时,**Rust 信任编译器**。
> 代价:编译器很严格,磨合期会经常被它"教育"。

## 三、性能:为什么敢说"接近 C"

- **无 GC**:没有运行时垃圾回收器,没有暂停
- **零成本抽象**:泛型/迭代器在编译期展开,不产生运行时开销
- **静态分发**:调用在编译期确定,不查虚表
- 实测:rg 比 grep 快 3-10 倍,不全是语言功劳(并行/算法),但语言没拖后腿

## 四、Rust vs C vs Go(一句话对比)

| | C | Go | Rust |
|---|---|---|---|
| 内存安全 | ❌ 手动 | ✅ GC | ✅ 编译期 |
| 性能 | 顶级 | 中上 | 顶级 |
| 上手难度 | 中(但坑多) | **低** | **高** |
| 开发速度 | 慢 | 快 | 前期慢,后期稳 |
| 生态定位 | 内核/驱动 | 服务端/云 | 系统工具/内核/高性能服务 |
| 适合谁 | 必须写 C 的人 | 想快速写服务的人 | 要性能又要安全的人 |

## 五、现代工具链(魅力的一部分)

```
cargo new mytool      ← 新建项目(自带 git/测试框架/文档框架)
cargo add clap        ← 加依赖(类似 npm install)
cargo build / run / test / fmt / clippy   ← 构建/运行/测试/格式化/静态检查
cargo publish         ← 发布到 crates.io(官方包仓库)
```

C 生态缺了 40 年的"官方包管理 + 构建一体化",Rust 出生就带着——**这是"重写经典工具运动"能爆发的基础设施原因**。

## 六、一句话总结

> Rust = C 的性能 + 无 GC + 编译期内存安全 + 现代工具链。
> 它不是银弹,但它是"系统级编程"这个领域 40 年来第一个真正的范式升级。

# 现代编辑器:Helix / Kakoune / Zed

## 一、挑战者全家福

## 二、选区哲学:Helix 与 vim 的本质区别

### vim 系:先移动,再操作

```
光标在行首 → 按 w 移到词首 → 按 d 删除"光标后面"
   移动在前,操作在后,光标是唯一的状态
```

### Helix/Kakoune 系:先选区,再操作

```
光标在词上 → 按 x 选中整个词(高亮!)→ 按 d 删除选中
   选区是常态:你永远"看得见"即将被操作的内容
```

| | vim/neovim | Helix/Kakoune |
|---|---|---|
| 状态 | 光标 | **选区**(默认选中当前词/行) |
| 操作 | `dw` = 移到词 + 删 | `d` = 删当前选中 |
| 可视化 | 操作前不知道影响范围 | 操作前高亮预览 |
| 多光标 | 插件实现 | **内置**(`C` 选中同词所有出现) |
| 模式 | normal/insert/visual... | normal/insert/select 三个 |

> [!note] 这是设计哲学的分歧,不是优劣
> vim:组合命令的表达力(动词×名词);Helix:所见即所删的安全感。
> 40 年肌肉记忆 vs 5 分钟上手——各有取舍。

## 三、Helix 详析

**核心卖点:出厂即全配**

| 功能 | vim 需要 | Helix 出厂 |
|---|---|---|
| LSP 补全/跳转 | 装插件 + 配服务器 | ✅ 自动发现 |
| 语法高亮 | 装 Treesitter + 语法包 | ✅ 内置 |
| 多光标 | 装插件 | ✅ 内置 |
| 文件树 | 装插件 | ✅ 内置 |
| 主题 | 装配色 | ✅ 十几个内置 |

**代价**:

- **几乎没有插件生态**(官方不提供插件 API,刻意为之)
- 键位自成一派,只在 Helix 内有效
- 可编程性有天花板——复杂工作流无法脚本化

## 四、Zed:LSP 之外的路线

- Atom 作者 Nathan Sobo 的新作(Rust + GPUI)
- 定位:原生 IDE 级性能(启动毫秒级)+ AI 集成 + 多人协作
- 关键:它**不在终端里跑**(GUI 应用),不抢 nvim 的"终端场景"
- 现状:增长快,但闭源核心 + 生态未成气候

## 五、nvim vs Helix:一页结论

| 维度 | nvim | Helix |
|---|---|---|
| 插件生态 | 数千插件,十年积累 | 几乎没有 |
| 配置 | Lua/声明式,折腾 | 内置为主 |
| 键位 | vim 标准,**全行业通用** | 自成一派 |
| 上手时间 | 数周(教程+习惯) | 数小时 |
| 上限 | 无限 | 有天花板 |
| 适合 | 愿意投资学习/配置 | 开箱即用党 |

**现今流行情况**:nvim 仍是王(生态碾压);Helix 是增长最快的新势力;Zed 走 IDE 路线不直接竞争。

> [!tip] 给你的建议
> 你刚完成 nvim 181 题实操教程——vim 键位正在变成肌肉记忆,这是"学一次,
> 到处用"的投资(服务器/IDE 模式/tmux 全通用)。Helix 的键位只在 Helix 里有效。
> 结论:**继续 nvim;Helix 作为参照了解即可**。

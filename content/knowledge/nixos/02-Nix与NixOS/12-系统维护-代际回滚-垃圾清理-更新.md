# 12 · 系统维护 —— 回滚、清理、更新

> 上一篇：[[11-home-manager入门]] · Nix/NixOS 部分完结 → [[01-显示服务器-从X11到Wayland]]

## 1. 代际：复利优势，但记住清理

每 rebuild 产一个新代际。开机时 systemd-boot 菜单里列这些代际：
```
NixOS - Configuration 142 (2026-07-26)
NixOS - Configuration 141 (2026-07-25)
...
```

### 滚回上一个代际
```bash
sudo nixos-rebuild switch --rollback
```
重启后开机菜单选旧的也行。

### 手动选某代际激活
```bash
sudo nix-env -p /nix/var/nix/profiles/system --list-generations
sudo nix-env -p /nix/var/nix/profiles/system --switch-generation 142
/nix/var/nix/profiles/system/bin/switch-to-configuration switch
```

### 清理老代际
```bash
sudo nix-collect-garbage                    # 删掉没有 profile 引用的 store 路径
sudo nix-collect-garbage -d                 # 同时删除超过 30 天的 profile 代际
sudo nix-env -p /nix/var/nix/profiles/system --delete-generations +5  # 只留最近 5 个
```

## 2. /nix/store 会越来越大

```bash
# 看 store 多大
du -sh /nix/store

# 看它在存什么（包 / 代际系统 / 源码）
nix path-info -rSh /run/current-system | head -20

# 清孤立路径（无依赖也没被任何 profile 引用）
sudo nix-store --gc

# 输出：freed 15.2 GiB  ← 偶尔清一次不亏
```

没有 profile 引用的老代际 + 孤立包 + 未使用的代码 → collective garbage。

**日常**：一个月清一次够了，不用频繁。

## 3. 更新系统（追 nixpkgs + flake inputs）

```bash
# 步骤 1：更新 flake.lock（把所有依赖引向最新版）
nix flake update --flake ~/nixos-config

# 步骤 2：只构建验证
nixos-rebuild build --flake ~/nixos-config#loysan

# 步骤 3：构建成功 → 切换
sudo nixos-rebuild switch --flake ~/nixos-config#loysan

# 步骤 4：顺手清理
sudo nix-collect-garbage -d
```

**更新频率**：nixpkgs-unstable 每天几十个包更新。稳定版（nixos-25.11）每月几个安全修复。
你不需要天天追——**一个月一次**就很勤快了。出了 CVE 才紧急追。

### 如果构建失败
`nixos-rebuild build` 先跑的 → 构建失败不用慌，系统没变。
看一下 error → 可能是某个包临时死了（上游 tar.gz 被删）→ 等一天再追。
也可能是某个 flake input 不兼容新 nixpkgs → `nix flake lock --update-input nixpkgs`（只追一个）。

### 如果切了系统发现有问题
`sudo nixos-rebuild switch --rollback`（秒切回刚才的）。

## 4. nix store 优化

nix 有自动**去重**——两个路径内容一样的文件共享 inode。看效果：
```bash
nix store optimise   # 硬链接去重
# 首次跑会看到 freed 一大截，之后就边际递减
```

## 5. 出了严重问题怎么救

### 场景一：系统起不来了（刚 rebuild 完重启卡 logo）
→ 开机 systemd-boot 菜单选**上一个代际**（物理按键）。进去。

### 场景二：想切到旧代际但进不去系统
→ Live USB 启动 → mount / → `nixos-enter` → 改配置 → `nixos-rebuild boot` → 重启

### 场景三：配置写了个死循环 → rebuild 超内存
→ `nixos-rebuild build` 设 `--max-jobs 1 --cores 1` 限制并行度。
如果是无限递归 eval → `nix flake check` 在 rebuild 前就能抓住。

### 场景四：sudo 坏了
万中无一。NixOS 的 sudo 是声明式的，不手动改 → 基本不会坏。

## 6. 定期做的事（建议）

| 频率 | 做什么 |
|---|---|
| 每改完一次配置 | `nixos-rebuild build`（免 sudo 验证） |
| 每次 switch 后 | git commit（有意义的 message） |
| 每周 | `sudo nix-collect-garbage` |
| 每月 | `nix flake update && build` 试追新版 |
| 每季度 | `sudo nix store optimise` |

## 7. 查看系统状态

```bash
nixos-version                                    # nixpkgs 发行版
nix flake metadata ~/nixos-config --json | jq   # flake 依赖版本
systemctl list-timers                            # 有什么自动任务
systemctl --failed --no-pager                    # 什么服务挂了
sudo nix-store --gc --print-roots | head -20     # 谁在阻止垃圾回收
```

## 8. 一句话

> 代际是 NixOS 的"后悔药"，GC 是"清理费"。
> 更新 = update lock → build 验证 → switch 切换 → gc 清理。
> 月更一次，稳得很。

# 数据管线：点位编辑桥按文法规格化匹配列名（容忍 >类型 后缀）

## 背景与现象

两个点位编辑器（阵型/路径）连不上数据通路，导出工具正常。真实报错：`路径.duowei 缺字段: Custom-Points/Random-BoundInner/Random-BoundOuter`。根因：表格几何列已加 `>类型` 后缀（`Offsets>List<Vector2>`、`Custom-Points>List<Vector2>`、`Random-BoundInner>Vector2`、`Random-BoundOuter>Vector2`），而 server.py 的 `TABLES`（required 清单 + columns 逻辑→物理映射）按旧物理列名精确匹配 → 失配。

## 交付物

1. `server.py` 列匹配**文法规格化**（非更新硬编码名）：物理字段名先剥 `>类型` 后缀（与导出器 parse_name 同一文法：首个 `>` 前部分）再与 required/columns 逻辑名比对；读写一律解析到**实际物理列 fid**（带后缀的真实列）——required 校验、/list 形态判定、/record 读、POST /record 最小手术写回全部走 fid，列名再怎么加后缀都不影响。TABLES 配置本身不动（逻辑契约不变）。
2. 写回路径专项验证：fmt-R 归一化、revision+1、updatedAt、原子替换逻辑对带后缀列照常生效（物理列 fid 没变，理论上写回本就按 fid 或按名——以实际代码为准，若按名写则必须改为 fid）。
3. 验证（不碰真实表格数据）：
   - 起服务（或临时实例）：GET /list?table=formation → 329 条；/list?table=path → 81 条
   - GET /record 抽查：path 一条 Custom（Points 非空文本）+ 一条 Random（BoundInner/BoundOuter/WaypointCount）；formation 一条 Offsets
   - 写回测试在 **TEMP 副本**上做：复制两表 .duowei 到临时目录，以 `--dir` 指向临时目录起临时端口实例，POST /record 改一个点位值 → 200、重读一致、revision+1、临时目录中验证 JSON 结构完好；测完删临时实例与副本
   - 服务端日志无新增异常
4. README「常见问题」如提及该报错则同步（无则不加）。

# 数据管线：类型规则二批（精度/枚举引用）+ 导出原子性与列名匹配

## 背景（已侦查确诊）

- 「点一次运行导出不完整、要点几次」根因：表格编辑中间态/列名与配置失配 → 导出器快速 FAIL（实测 0.2s exit=1，如 事件监听.op 改名 Op>CompareOp 后 config compare.columns 里的 "op" 匹配不上 → 该表 unknown → 级联 内嵌失败，两张表产物缺失）。且失败时**半成品落盘**：FAIL 的表 json 不写（旧文件残留）、cs 目录已先清空 → 产物不完整且新旧混杂。
- `>类型` 后缀在单选列上的语义（负责人拍板）：**`A>B` 中 A=字段名（保持表类成员名），B=实际使用的枚举类型名（引用既有枚举，不生成新枚举）**；无后缀则按字段名生成枚举（现状）。
- number 字段类型按**字段属性精度**决定（负责人拍板）：`numberFormat.decimals` 存在且 >0 → 1~6 位=float、>6 位=double（值全整数也按属性走，如 Duration decimals=2 → float）；decimals=0 或缺省 → 按值扫描推导（现状）。

## 交付物

### A. 枚举引用规则（`>类型` on singleSelect）

`GameData/tools/Program/duowei_export.py` `_make_member`：singleSelect + type_hint → 成员 ctype=type_hint（枚举类型名引用，如 CompareOp，位于 KFramwork 命名空间，生成文件已有 using KFramwork），**不注册/不生成新枚举**；json 值仍输出选项名文本（走 opt_name 转换，同 enum kind）。无 type_hint → 现状按字段名生成枚举。

### B. number 精度规则

`infer_simple_ctype`：读取字段元数据 `numberFormat.decimals`（@合并组各源列不一致时 FAIL）；规则见背景。Duration（关卡表 decimals=2）应生成 `public float Duration`。

### C. 导出原子性 + 匹配健壮性（修「要点几次」）

1. **原子落盘**：全部表 json + 全部 cs 先生成到内存/临时目录，**FAIL=0 才统一写盘**；有 FAIL 时不动现有产物（或先备份再回滚）。杜绝半成品与新旧混杂。
2. **detail 签名与 compare.columns 按「解析后输出名」匹配**（实测缺陷：签名比对用原始列名，`op>CompareOp` 解析后输出名为 `op` 本应命中却失配 → 两张明细表 unknown → 4 FAIL 级联）；比对同时大小写不敏感（表列名策划手写，大小写漂移不应断链）；命中后成员名以表列名（解析后输出名）为准。
3. 事件条件表存在 `新字段` 列（非 ASCII）：按现有净化规则处理为合法成员或明确 FAIL 提示，不得静默。

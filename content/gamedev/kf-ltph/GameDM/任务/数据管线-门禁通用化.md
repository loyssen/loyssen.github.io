## 背景与拍板

## 交付物

`GameData/tools/Program/ExportCheck/` 重建为**零项目知识**的通用装载门禁：

1. **删除**：Program.cs 中全部项目特定断言、条数快照常量、字段名抽查、__type 分布数字。
2. **保留（本就通用）**：
   - 编译面：csproj glob 编入 Generated 全部 .cs + 类型链接检查（`N/N 类型链接`）
   - Shims.cs：KFramwork.ActorData/AbstractData、Vector2 平台垫片（框架/引擎依赖替身，非项目数据知识；ActorData 垫片含 Id/Name string 成员）
3. **装载面通用化**（核心，反射驱动、无任何硬编码名）——对 `Export/*.json` 逐个：
   a. 按文件名定位同名生成类型 T（含继承链）；JsonConvert 反序列化 `List<T>`，断言装载成功且条数 == JArray.Count
   b. **键覆盖校验**：每条 JToken 记录的每个键必须落在该类型家族成员集内——基类链成员 ∪（存在子类时）全部子类成员并集（平铺子类增量键无 __type 场景）；带 `__type` 键的记录，`__type` 值必须能解析为已生成子类类型且键 ⊆ 该子类成员集
   c. 嵌套递归：值为对象/数组的键，对其元素递归按对应成员类型做同样校验
   d. 数值/字符串形态粗校验：json 数值键对应成员为数值类型、数组键对应 List/数组成员（键覆盖天然涵盖，按需实现）
4. **输出**：每 json 一行 `[PASS/FAIL] <类名> 条数=N 键覆盖 OK/缺 xxx` + 总计 + 退出码（0=全过）
5. **通用性自证**：把 ExportCheck 里出现的标识符清单列进汇报（应仅剩：json 文件名遍历、反射 API、Newtonsoft、垫片类型名——不得出现任何业务表/字段/条数）

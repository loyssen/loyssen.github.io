# 条件事件库

> **统一事件表**：`StreamingAssets/ConditionEvent/` 下全部事件定义（GUID 全局唯一、跨关卡复用）。关卡 JSON 的 `Timeline` 只存 **EventId(GUID) + TriggerTime**，事件定义在本库按 GUID 索引；各关卡文档的事件表**只显示事件名 + 触发时间**，GUID 映射以本文档为唯一权威。数值以 JSON 为准。
> 现状定位：事件数据已随三表 Luban 原生化迁移——`StreamingAssets/ConditionEvent/` 目录已不存在，现行数据链为 `.duowei` 编辑源 → xlsx → Luban 产物 `Assets/StreamingAssets/luban/cfg_tbeventlisten.json`/`cfg_tbeventdatacondition.json`（以 EventName 索引，无 GUID 字段）；本文 GUID 映射表为概率制时代参考快照，现行事件以 Luban 数据链为准。本库由设计层（GameDD）维护，策划文档不承载 GUID 细节。

## 四、使用约定

1. **GUID 是唯一标识**：事件名可重复（如同名"紫金葫芦 循环"有 DC 版/无 DC 版两版），区分靠 GUID；关卡 Timeline 引用必须用 GUID
2. **条件列速记**：`停`=StopOnCondition；`DC(路径 op 值)`=数据条件（op：≥/>/==/</≤/≠）；`FishKilled(名)`=监听击杀事件（FishName 用 PascalCase）；`延迟Ns`=EventDelay；`链→N`=TriggerEventIds 数量
3. **数量 0 = 哨兵事件**：不生成实体，仅用于条件监听 + 链触发
4. 新增事件：在对应分类文件新增 JSON → 重新生成本文档（事件名/GUID 映射 + 参数）
5. 各关卡文档事件表（如 [[龙宫海域#八一事件表7列]]）与本库联动：改事件参数只需维护 JSON + 本库，关卡文档无需改动

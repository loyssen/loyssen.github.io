# 10 LSP 智能编程 · 解答

> [!warning] 先做题再看
> 答案看一眼就记住了,但那是"知道",不是"会"。卡住 2 分钟再翻这里,
> 看完合上文档,回到题目重新做一遍。

> [!note] 本机环境速览(解答里都用这套)
> - LSP 键位:`gd` 定义 / `gr` 引用 / `K` 悬浮文档 / `<leader>rn` 重命名 / `<leader>ca` 代码操作 / `<leader>k` 诊断浮窗 / `[d` `]d` 诊断导航
> - 诊断列表:`<leader>fd`(telescope)
> - 补全:blink.cmp 自动弹出,回车确认;签名帮助已开启(输入 `(` 后自动显示)
> - 格式化:conform 保存时自动格式化(本机靠 ts_ls 兜底,只重排缩进、不拆行);手动用 `:lua vim.lsp.buf.format()`——`:Format` 命令本机不存在(conform 只注册了 `:ConformInfo`)
> - 练习文件都是 `.txt`,不会触发 LSP。每题先把练习文件 `cp` 成 `.ts` / `.tsx` 再打开
> - 章节目录已放好 `tsconfig.json` + `react.d.ts`:ts_ls 会把整个 `练习/` 目录当成一个 TS 项目,155/156 的 react 相关诊断和自动导入才可用
> - 内联提示(题 163):ts_ls 默认把所有内联提示都关掉了,必须先注入配置(见题 163)

## 题 152:代码补全和建议

**操作解法(按键)**:打开文件后先删标记文字(标记在 `calculateTotal(|)  ← 光标位置` 一行上):

```
:g/← 光标位置/s/  ← 光标位置//   删掉行尾标记文字
:g/|)/s/|//                       删掉 | 保留 )
:w                               保存,让 ts_ls 开始分析
```

**操作解法(按键)**:光标放进 `calculateTotal(` 的括号里:

```
i                 在 ( 后面进入插入模式
   签名帮助窗口自动弹出:price: number, quantity: number, taxRate: number
10, 20, 0.05      按提示输入参数
<Esc>             回到普通模式

新起一行体验函数名补全:
const total = calc   输入 calc,补全菜单弹出 calculateTotal
回车                 确认(本章统一回车确认)
```

> [!warning] 参数名提示从哪来(实测修正)
> 原题说"输入 pri 补全菜单弹出 price 参数名"——本机 ts_ls 实测没有参数名补全项,
> 补全菜单给的是**函数名**(`calc` → `calculateTotal`)。
> 参数名提示来自**签名帮助窗口**(blink 已开):光标在 `(` 里窗口自动显示
> `price: number, quantity: number, taxRate: number`,按它手输参数即可。

**关键命令解析**:

| 操作 | 作用 |
|---|---|
| 输入即弹出 | blink.cmp 打字时自动弹补全菜单(不用按触发键) |
| 回车 | 确认选中的补全项 |
| C-n / C-p(或 ↑/↓) | 在补全项之间移动 |
| C-e | 关闭补全菜单 |
| 签名帮助窗口 | 输入 `(` 后自动弹出,显示形参名和类型;实参位置会高亮当前参数 |

## 题 153:跳转到定义和引用

**操作解法(按键)**:打开文件后先删掉 import 行(目录里没有 `./utils` 模块,留着会报红):

```
:g/^import /d      删掉 import 行
:w                 保存,让 ts_ls 分析
```

**操作解法(按键)**:

```
光标放到最后一行 formatDate(new Date()) 的 formatDate 上
gd              跳到定义(export function formatDate 那行)
Ctrl+o          跳回原位置(跳转历史后退)
Ctrl+i          再跳过去(跳转历史前进)
gr              打开引用列表,回车跳到调用处
```

> [!tip] 为什么必须先删 import 行?
> 单文件练习没有 `./utils` 模块,ts_ls 会报 "Cannot find module './utils'",
> 红色报错不影响 gd/gr,但干扰视线。删掉它诊断才干净。
> 真实项目里 gd 会直接跳到别的文件——这里是单文件,定义和调用必须同文件才能跳。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `gd` | go to definition,跳到符号定义处 |
| `gr` | go to references,列出所有引用该符号的位置 |
| `Ctrl+o` | 跳到上一个位置(跳转历史) |
| `Ctrl+i` | 跳到下一个位置,和 `Ctrl+o` 配对往返 |

## 题 154:代码重命名

**操作解法(按键)**:光标放到 `oldFunctionName` 上(定义或任意一处调用都行):

```
<leader>rn        弹出重命名输入框,默认带旧名字
newFunctionName   输入新名字
回车              确认,定义 + 2 处调用一次全改
```

> 实测:本机 ts_ls 返回 3 处编辑(第 1 行定义、第 6、7 行两处调用),全部改成新名字。
> 局部变量 `oldVar` 不会被误改——重命名只动符号本身。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `<leader>rn` | rename,LSP 重命名符号 |
| 重命名输入框 | 默认带旧名字,直接输入新名回车 |
| 重命名范围 | 符号的所有引用处,不只当前文件(单文件练习里是 3 处) |
| `u` | 撤销重命名,全部恢复 |

## 题 155:代码诊断和错误修复

**操作解法(按键)**:`.tsx` 后缀文件,打开后保存触发诊断:

```
:w              保存,ts_ls 分析,useEffect 行出现诊断标注
]d              跳到下一个诊断
[d              跳到上一个诊断
<leader>k       打开诊断详情(浮动窗口,完整报错文案)
<leader>fd      telescope 诊断列表,全文件问题一目了然
```

**修复**:

```
光标放到 useEffect 上
<leader>ca      代码操作列表
"Remove unused declaration for: 'useEffect'"  回车
:w              保存,诊断消失
```

> [!warning] 诊断文案(实测修正)
> 本机 ts_ls 报的文案是:
> `'useEffect' is declared but its value is never read`
> (原题写的 "is defined but never used" 是 VS Code 的措辞,本机不是这句,认准本机文案)
> 另外本机还有 "Cannot find module 'react'" 和 JSX 的报错?——章节目录的 `tsconfig.json` + `react.d.ts` 已消除这两条,只留未使用的诊断。删掉 react.d.ts 或 tsconfig 后这两条会回来,不影响练习。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `]d` | 跳到下一个诊断 |
| `[d` | 跳到上一个诊断 |
| `<leader>k` | 查看当前诊断的详细信息 |
| `<leader>fd` | telescope 诊断列表,一眼看到全部问题 |
| 诊断内容 | "declared but its value is never read" = 导入了但没用 |

## 题 156:自动导入

**操作解法(按键)**:打开 `.tsx` 文件,保存后 `useState` 报 "Cannot find name 'useState'":

```
光标放到 useState 上
<leader>ca         打开代码操作列表
"Add import from 'react'"   回车
:w                 保存,红色报错消失
```

> [!warning] 为什么本机能出现 "Add import from 'react'"?
> react 类型包本机没装(node_modules 里没有 @types/react),ts_ls 本来不知道 react 模块有什么。
> 章节目录的 `react.d.ts` 用 `declare module "react"` 声明了 `useState`,
> ts_ls 才能给出这个自动导入。**别删这两个文件**(`tsconfig.json` + `react.d.ts`)。
> 没它们时代码操作只剩 "Add missing function declaration 'useState'"(在本地声明一个函数,不是你要的导入)。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `<leader>ca` | code action:列出当前位置可用的 LSP 操作(修复/重构/导入) |
| "Add import from 'react'" | ts_ls 自动补上 `import { useState } from "react";` |
| 快速修复 | 每个报错位置都能 `<leader>ca` 看修复选项 |

## 题 157:代码格式化

**操作解法(按键)**:先故意弄乱,再保存:

```
光标在第 2 行 const x 那行,按 J 把两行声明挤成一行,再把缩进打乱(按 < 或 x 删空格)
:w              保存,自动格式化,缩进恢复
```

**手动格式化**(本机 `:Format` 命令不存在,实测确认):

```
:lua vim.lsp.buf.format()    手动格式化当前文件
```

> [!warning] 本机格式化现状(实测)
> - conform 配置了保存时格式化,但 prettierd / prettier 都没安装,
>   实际是 **LSP fallback 兜底**:ts_ls 的格式化服务在保存时自动重排缩进。
> - 所以:保存后**缩进一定恢复**,但**不会拆行**——你挤成一行的两个语句
>   仍在一行上(只是被缩进对了)。想拆行要补装 prettierd(nix 配置里加包),本章不强求。
> - `:Format` 命令本机不存在(conform 只注册了 `:ConformInfo`),手动格式化用上面的 `vim.lsp.buf.format()`。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `:w` | 保存,自动格式化(本机走 ts_ls LSP 格式化) |
| `:lua vim.lsp.buf.format()` | 手动格式化当前文件(`:Format` 本机不存在,用这个) |
| 格式化范围 | 整个文件,规则由 formatter 决定,别用手敲空格对齐 |

## 题 158:代码折叠和展开

**操作解法(按键)**:打开文件后**先开折叠**(本机默认 `foldmethod=manual`,不设折叠没法用,实测确认):

```
:set foldmethod=indent   按缩进折叠
```

**操作解法(按键)**:

```
光标放进 constructor 方法里
zc              折叠当前块 → constructor() {...}
zo              展开当前块
za              切换折叠/展开
光标移到下一个方法,重复 zc
zM              全部折叠
zR              全部展开
```

> 实测:indent 折叠下每个方法(缩进一级)都是独立的折叠块,zc 逐个收起来就是
> 类里 3 个 `{...}` 行;zM 会把整个类体也折掉,再 zR 全部恢复。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `:set foldmethod=indent` | 本机必需前置:默认 foldmethod=manual,zc 全部失效 |
| `zc` | fold close:折叠光标所在的块 |
| `zo` | fold open:展开 |
| `za` | 切换折叠/展开 |
| `zM` / `zR` | 全部折叠 / 全部展开 |
| 折叠依据 | 缩进结构(treesitter 也可,本机未配,用 indent 即可) |

## 题 159:函数签名帮助

**操作解法(按键)**:打开文件后删标记文字,光标放括号里:

```
:g/← 光标位置/s/  ← 光标位置//   删行尾标记
:g/|)/s/|//                       删 | 保留 )
:w                               保存

光标放到 Math.max( 的括号里
    签名帮助窗口自动弹出:max(...values: number[]): number
K               光标放 Math.max 上 → 悬浮文档:签名 + 说明
输入 3, 9, 7    当前参数在窗口里高亮,跟着光标走
```

> [!warning] 签名文案(实测修正)
> 本机 TS 5.9 的签名是 `max(...values: number[]): number`(一个 rest 参数),
> 不是原题写的 `(value1, value2, ...values)` 老签名。认准本机这条即可,
> 要练"多参数"的感觉就找别的函数,签名帮助的机制是一样的。

**关键命令解析**:

| 操作 | 作用 |
|---|---|
| 输入 `(` 后等待 | 签名帮助窗口自动弹出,显示参数名和类型 |
| `K` | 悬浮文档:函数签名 + 详细说明 |
| C-n / C-p | 有多个重载时切换签名 |
| 输入参数 | 当前参数高亮跟随光标,不会写错位置 |

## 题 163:内联提示

**操作解法(按键)**:本机 ts_ls 默认**所有**内联提示都关闭(实测:enable 之后 0 条提示),必须先注入配置:

```
:lua vim.lsp.buf_notify(0, "workspace/didChangeConfiguration", { settings = { typescript = { inlayHints = {
    includeInlayParameterNameHints = "literals",
    includeInlayFunctionParameterTypeHints = true,
    includeInlayFunctionLikeReturnTypeHints = true,
    includeInlayVariableTypeHints = true,
    includeInlayPropertyDeclarationTypeHints = true,
} } } })
```

然后开启显示:

```
:lua vim.lsp.inlay_hint.enable(true)     开启
:lua vim.lsp.inlay_hint.enable(false)    关闭
```

> [!warning] 命令写法(实测修正)
> 本机 nvim 0.11.7 里 `enable(true)` / `enable(false)` 正确;
> 原题写的 `enable(0, true)` 在本机会报错
> ("expected boolean, got number")——别用。0.11 的按 buffer 写法是
> `enable(true, { bufnr = 0 })`。
> 想永久开启:在 nixvim 的 ts_ls 配置里加 `settings.typescript.inlayHints.*`(见题末)。

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `vim.lsp.buf_notify(...)` | 给 ts_ls 注入 inlayHints 偏好(本机必需前置,ts_ls 默认全关) |
| `vim.lsp.inlay_hint.enable(true)` | 开启内联提示显示(nvim 0.11 写法,参数是布尔) |
| 内联提示 | 直接写在代码里的灰色提示:参数名、类型、返回类型 |
| 关闭 | `enable(false)` |

> 实测效果:注入配置 + enable 后,`greet("John", 30)` 显示 `name:` / `age:` 参数名提示,
> `greet` 函数签名处显示 `: void` 返回类型提示。
> 长期方案:在 nixvim 的 `lsp.servers.ts_ls.settings` 里配置
> `typescript.inlayHints`(对应上面注入的字段),重启 nvim 后不用每次手动注入。

## 题 165:LSP 工作区管理

**操作解法(命令)**:在任意 nvim 会话里执行:

```
:lua vim.lsp.buf.add_workspace_folder("/home/loysan/nixos-config/notes/nvim")
:lua print(vim.inspect(vim.lsp.buf.list_workspace_folders()))
:lua vim.lsp.buf.remove_workspace_folder("/home/loysan/nixos-config/notes/nvim")
:lua print(vim.inspect(vim.lsp.buf.list_workspace_folders()))
```

查状态:

```
:LspInfo    当前 buffer 附加了哪些服务器、项目根目录是什么
```

**关键命令解析**:

| 命令 | 作用 |
|---|---|
| `vim.lsp.buf.add_workspace_folder(path)` | 添加一个工作区目录(monorepo 的第二个根) |
| `vim.lsp.buf.list_workspace_folders()` | 列出当前所有工作区目录 |
| `vim.lsp.buf.remove_workspace_folder(path)` | 移除,参数要和添加时完全一致 |
| `:LspInfo` | 排查"LSP 怎么没生效"时先看它 |
| 对 LSP 的影响 | 通知已连接的服务器 `workspace/didChangeWorkspaceFolders` |

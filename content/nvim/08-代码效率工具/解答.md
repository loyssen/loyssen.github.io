# 08 代码效率工具 · 解答

> [!warning] 先做题再看
> 答案看一眼就记住了,但那是"知道",不是"会"。卡住 2 分钟再翻这里,
> 看完合上文档,回到题目重新做一遍。

> [!note] 本机环境速览(解答里都用这套)
> - 补全:blink.cmp(super-tab 预设)+ LuaSnip + friendly-snippets
> - `<Tab>`:菜单打开时选中并接受;片段展开后跳到下一个占位符;`<S-Tab>` 回跳;`<C-space>` 唤出菜单
> - 占位符按编号 `${1}` `${2}` ... 顺序跳转,`$0` 是最终落点;同一编号出现多次会联动同步
> - 选项列表(choice)占位符:`<Tab>` 会直接跳走**不会**循环选项,循环要 `:lua require("luasnip").change_choice(1)`(回退用 `-1`),或干脆把选项文本删掉重输
> - 练习文件都是 `.txt`,friendly-snippets 按文件类型加载片段,先 `:set ft=javascript`(或对应类型)才有片段
> - conform 保存即格式化:js/ts/python 有 prettierd/black,展开后 `:w` 自动排版;html/css **没有**格式化器,不排版
> - friendly-snippets 本体在 nix store(只读),自定义片段写在 `nixos-config/nixvim/plugins/snippets.nix`
> - 本机 LuaSnip 是 2.x:`get_snippets()` 返回"文件类型 → 片段表",`t()` 文本节点里不能写换行(多行用行数组 `t({...})`)

## 题 124:基础代码片段使用

**操作解法(按键)**:打开文件后先指定文件类型,再删光标标记行:

```
:set ft=javascript   先指定文件类型,.txt 默认没有 JS 片段
ggdd                 删除第 1 行的光标标记
function             输入触发词,菜单弹出,第一项就是 Function Statement
<Tab>                接受并展开
functionName         填入函数名(占位符 1)
<Tab>                跳到下一个占位符
params               填入参数(占位符 2)
<Tab>                跳到函数体($0 落点)
// 函数体            填入函数体内容
```

`function` 片段展开的完整结构:

```js
function name(params) {
  // 函数体
}
```

> [!note] 菜单里第一项不是片段怎么办?
> 如果菜单第一项是 LSP 或 buffer 条目(带别的图标),按 `↑↓` 选中带"片段"图标的条目再按 `<Tab>`。

## 题 125:条件语句片段

**操作解法(按键)**:

```
ggdG         清空文件(全选删除)
for          输入触发词,<Tab> 展开
```

`for` 展开的完整结构(`index` 出现 3 次、`array` 出现 2 次,全部联动):

```js
for (let index = 0; index < array.length; index++) {
  const element = array[index];
  // 这里是 $0 落点
}
```

**占位符顺序**:`index` → `array` → `element` → 函数体($0)。

**联动占位符实测**:把 `index` 改成 `i`,声明、条件、`index++` 三处同步变;`array` 两处同理。改一处,其余自动跟上,这正是片段效率的核心体验。

**if 重试**(初始文件就是它展开的):清空后输入 `if` → `if (condition) { ... }`,与目标状态对比看占位符结构。

## 题 127:导入和导出片段

**操作解法(按键)**:每组都是"清空 → 输入触发词 → `<Tab>` 填占位符":

| 触发词 | 展开结果 | 占位符顺序 |
|---|---|---|
| `id` | `import {$2} from '${1:module}'` | **先 `module`(from 后面),再大括号内容** |
| `im` | `import ${2:*} from '${1:module}'` | 同上,先 module 后 `*` |
| `ia` | `import ${2:*} as ${3:name} from '${1:module}'` | module → `*` → name |
| `ed` | `export default ${1:member}` | member |
| `ec` | `export const ${1:member} = ${2:value}` | member → value |

**三个 import 触发词的区别**:

- `id` = import **destructured**:`import { x } from "..."`,具名导入
- `im` = import **module**:`import * from "..."`,默认导入(星号)
- `ia` = import **as**:`import * as name from "..."`,命名空间导入(给整个模块起名字)

**注意 `id` / `im` 的占位符顺序是反直觉的**:`${1:module}` 在 `from` 后面,`${2}` 在大括号里。展开后光标先落在 module 上,`<Tab>` 后才到大括号/星号。

`edf`(export default function)展开:

```js
export default function name (arguments) {
  // $0 落点
}
```

> [!note] 引号样式
> 片段展开用单引号(`'package'`),`:w` 时 conform(prettierd)统一成双引号,和目标一致,不用手工改。

## 题 128:异步代码片段

**操作解法(按键)**:`function` 起步,组合四个片段:

```
ggdG           清空文件
function       <Tab> 展开(光标已在 name 占位符上)
asyncFunction  填函数名
<Tab>          跳到 params 占位符
params         填参数
<Tab>          跳到函数体($0 落点)
<Esc>          退出插入模式,回到行首补 async
^i             跳到行首
async<Esc>     输入 async(片段里没有 async 版本)
j              回到函数体行
i              进入插入模式
trycatch       输入并 <Tab> 展开,光标已在 catch(error) 占位符上
error          直接输入替换(占位符默认文本处于选中状态)
<C-e>          关掉补全菜单(刚输入字符菜单会弹出,不关 Tab 会接受补全)
<Tab>          跳到 try 体($0 落点)
ca             输入并 <Tab> 展开,光标已在 name 上
result         填 result
<Tab>          跳到 value
asyncOperation()  填 value
<Tab>          跳出 ca,回到 try 体末尾
return result; 手动输入
<Tab>          结束片段
j              手动把光标移到 catch 块(跳转链到不了这里)
ce             输入并 <Tab> 展开
error          填 error(或直接 <Tab> 接受默认)
```

**各片段展开结果**:

```js
// trycatch
try {
  // $0 落点
} catch (error) {
  // 展开时是空的
}

// ca(const assignment awaited)
const result = await asyncOperation();

// ce
console.error(error);
```

**Tab 占位符顺序**:`function` 的 name → params → 函数体落点;`trycatch` 的 error → try 体落点;`ca` 的 name(result)→ value。教学说的顺序 `name → params → error → result → value` 就是这条链。

**`asf` 和组合方案的差别**:`asf` 展开是:

```js
async function (arguments) {
  // $0 落点
}
```

**它没有函数名占位符**(直接 `async function`,name 得手写),所以教学的目标状态(有名字、内嵌 try/catch)用组合方案。

## 题 129:React 组件片段

**操作解法(按键)**:组合 `im` + `function` + `ed`:

```
ggdG           清空文件
im             <Tab> 展开(占位符顺序:先 module 再 *)
react          填 module
<Tab>          跳到星号占位符
React          把默认的 * 改成 React
function       <Tab> 展开
ComponentName  填函数名(占位符 1)
<Tab>          跳到参数占位符
{ prop1, prop2 }  填解构 props
<Tab>          跳到函数体
return <div>{prop1}</div>;  手动输入
<Tab>          结束片段
ed             展开,member 填 ComponentName
```

**rfcn 试用**(记得先 `:set ft=javascriptreact` 才有 react 片段):

```js
const functionname = () => {
  return (
    <div>
      // $0 落点
    </div>
  )
}

export default functionname
```

`rfcn` 是箭头函数风格组件,和教学目标的 function 声明式不同,展开看过、撤销即可。

> [!note] 拆行交给 prettierd

## 题 130:Console 和调试片段

**操作解法(按键)**:每次"清空 → 触发词 → `<Tab>` 展开",5 个触发词的展开结果(实测):

```js
cl   → console.log(光标停在括号里,直接输入内容)
cv   → console.log('variable': variable)   ← 名字填一次,两处同步
ce   → console.error(直接输入内容)
cw   → console.warn(直接输入内容)
cod  → console.dir('variable': variable)   ← 同 cv,联动
```

**`cv` 联动实测**:展开后光标在 `${1}` 上(引号里的名字,默认文本 `variable` 被选中),直接输入名字(如 `user`),`console.log('user': user)` —— 引号里和参数里同时变。这是"同一编号占位符出现两次"的联动效果,`cod` 同理。

## 题 131:注释和文档片段

**操作解法(按键)**:先把文件类型切成 jsdoc 才能重建初始注释:

```
:set ft=jsdoc       关键!本机 jsdoc.json 只挂在 jsdoc 类型下
ggdG                 清空文件
/**                  <Tab> 展开文档注释模板
<Tab>                依次填 1 描述 → 2 @returns → 3 @param 名 → 4 参数描述 → 5 示例代码
```

`/**` 展开的模板(占位符按 1 → 2 → 3 → 4 → 5 跳):

```js
/**
 * ${1:What it does}.
 *
 * @param ${3:name} - ${4:Parameter description.}
 * @returns ${2:Type and description of the returned object.}
 *
 * @example
 * ```
 * ${5:Write me later.}$0
 * ```
 */
```

**目标行 `// TODO:` 手打**:friendly-snippets 里没有"行注释 TODO"片段(TODO 只存在于文档注释的 `@todo` 触发词里)。所以这题答案就是:清空后直接打字,顺便验证"没有现成片段 → 自定义片段的动机"。

> [!warning] `:set ft=javascript` 时看不到 `/**` 和 `@todo`
> 本机配置没有把 jsdoc 扩展进 javascript 类型,实测 `ft=javascript` 下 jsdoc 片段全部不加载。想重建/试用文档注释,必须先 `:set ft=jsdoc`。

## 题 132:测试代码片段

**操作解法(按键)**:

```
ggdG         清空文件
its          <Tab> 展开 it 同步版本
should do something  填测试描述(占位符 1)
<Tab>        跳到回调函数体($0 落点)
// Arrange   ↓ 函数体里手写三阶段(没有现成片段)
const input = "test";

// Act
const result = functionUnderTest(input);

// Assert
expect(result).toBe(expected);
```

**四个 it 变体的区别**:

| 触发词 | 展开 | 用途 |
|---|---|---|
| `its` | `it('desc', () => {...})` | 同步测试 |
| `it` | `it('desc', async () => {...})` | 异步测试(async 回调) |
| `itd` | `it('desc', (done) => {...})` | done 回调风格 |
| `itt` | `it.todo('desc')` | 待办标记,先占个坑 |

`desc` 展开:`describe('description', () => {...})`(初始文件就是它 + `its` 的组合)。

## 题 133:HTML 片段

**操作解法(按键)**:

```
:set ft=html
ggdG         清空文件
!            <Tab> 展开文档骨架(触发词就是英文感叹号)
<Tab>        占位符 1:lang(默认 "en",光标在 en 前面)
<Tab>        占位符 2:viewport 的 device-width(直接 <Tab> 跳过)
<Tab>        占位符 3:initial-scale(直接 <Tab> 跳过)
<Tab>        占位符 5:title(填 Document)——注意没有 4 号,直接跳 5
<Tab>        占位符 6:body 内容
```

**`!` 展开结果**(实测):

```html
<!DOCTYPE html>
<html lang="en">
<head>
	<meta charset="UTF-8">
	<meta name="viewport" content="width=device-width, initial-scale=1.0">
	<title>Document</title>
</head>
<body>
	${6}   ← 第 6 个占位符,光标在这,继续输入标签片段
</body>
</html>
```

> [!warning] 两个已知差异,不用纠结
> 1. `lang="$1en"` 里默认文本 `en` 跟在光标后面:要得到 `lang="zh-CN"`,输入 `zh-CN` 后把光标后的 `en` 删掉(或展开后整行改)。
> 2. `<meta>` 不自闭合(没有 `/>`),缩进是 tab——html 不在 conform 格式化列表里,`:w` 不排版。手动微调或接受,结构对即可。

**body 里加标签**:在 `${6}` 占位符处依次输入 `a` / `img` / `ul` / `li` 展开,例:

```html
<a href="$1">$2</a>
<img src="$1" alt="$2">
<ul>
	<li>$1</li>
</ul>
```

**`!` 和 `html5` 的区别**:`html5` 展开的骨架多一行 `<link href="css/style.css" rel="stylesheet">`(自带样式表引用),`!` 是纯骨架;触发词上 `!` 只要按一个键,`html5` 要打 5 个字符。

## 题 134:CSS 片段

**操作解法(按键)**:

```
:set ft=css
ggdG         清空文件
dis          <Tab> 展开 display 片段(触发词是 dis,不是 display)
```

`dis` 展开(带选项列表占位符,实测):

```css
display: none;   ← 光标在 none 上,默认第 1 个选项
```

**体验选项循环**:选项列表是 `none, block, inline, inline-block, flex, ...`。注意 `<Tab>` 在选项上会**直接跳走**(super-tab 只做占位符跳转),循环选项要用:

```
:lua require("luasnip").change_choice(1)    切下一个选项
:lua require("luasnip").change_choice(-1)   切上一个选项
```

(切几个选项感受一下,最后选 `flex` 或直接手输。)

**目标 grid 三行**:选项列表里**没有 `grid`**,css.json 里也没有 `gap` / `grid-template-columns` 片段——所以这三行是"半片段半手打":

```css
display: grid;                              ← dis 展开后,把选项文本改成 grid
grid-template-columns: repeat(3, 1fr);      ← 手打
gap: 1rem;                                  ← 手打
```

> [!note] 这题为什么不能全靠片段?
> friendly-snippets 的 css.json 只有 display 一个选项片段,grid 系列没有。这就是"自定义片段"的动机——下一题就自己造。

## 题 135:自定义代码片段

**操作解法**:新建配置文件 → 注册 → rebuild → 测试。

**第 1 步**:新建 `/home/loysan/nixos-config/nixvim/plugins/snippets.nix`:

```nix
{ ... }:
{
  programs.nixvim.extraConfigLua = ''
    local ls = require("luasnip")
    ls.add_snippets("javascript", {
      -- fetch 链:apicall
      ls.snippet("apicall", {
        ls.t('fetch("'),
        ls.i(1, "url"),
        ls.t({ '")', "  .then(response => response.json())", "  .then(data => {", "    // 处理数据", "  })", "  .catch(error => console.error(" }),
        ls.i(2, "error"),
        ls.t("));"),
      }),
      -- 箭头函数:arfn
      ls.snippet("arfn", {
        ls.t("const "),
        ls.i(1, "functionName"),
        ls.t(" = ("),
        ls.i(2, "params"),
        ls.t({ ") => {", "  // 函数体", "};" }),
      }),
    })
  '';
}
```

**第 2 步**:在 `/home/loysan/nixos-config/nixvim/default.nix` 的 `imports` 列表里加上一行(位置随意):

```nix
./plugins/snippets.nix
```

**第 3 步**:rebuild 并测试:

```bash
cd /home/loysan/nixos-config
sudo nixos-rebuild switch --flake .#loysan
```

重进 nvim,打开练习文件:`:set ft=javascript` → `ggdG` → 输入 `apicall` → `<Tab>` 展开,填 url 和 error;再试 `arfn`。

> [!note] 代码要点(为什么这么写)
> - `ls.snippet(触发词, 节点列表)` 定义整个片段;触发词在 `add_snippets("javascript", ...)` 表示只对 javascript 生效
> - `ls.t(文本)` 纯文本节点;**LuaSnip 2.x 的文本节点不能含换行**,多行文本用行数组 `t({ "第1行", "第2行", ... })`
> - `ls.i(编号, 默认文本)` 可编辑占位符,编号即 Tab 跳转顺序
> - 箭头参数故意不写括号(`response =>`):`:w` 时 prettierd 自动补成 `(response) =>`,和目标状态一致
> - 修改触发词:改 `ls.snippet("arfn", ...)` 的第一个参数(如 `"arrowfn"`),rebuild 即生效

**三个节点的作用**(检验清单要求能说出来):

| 节点 | 写法 | 作用 |
|---|---|---|
| `s` (snippet) | `ls.snippet(触发词, {...})` | 片段容器,最外层 |
| `t` (text) | `ls.t("文本")` | 固定文本,不参与跳转 |
| `i` (insert) | `ls.i(1, "默认值")` | 可编辑占位符,按编号跳转 |

## 题 136:Python 代码片段

**操作解法(按键)**:

```
:set ft=python
ggdG         清空文件
class        <Tab> 展开,classname 填 ClassName
<Tab>        跳到类体($0 落点)
defs         <Tab> 展开方法片段,方法名填 __init__(占位符 1)
<Tab>        跳到参数占位符 2(self 已经自动带上,补 param)
<Tab>        跳到方法体
self.param = param   手动输入
<Tab>        结束
defs         再展开 method 方法,self 后补空参数
pass         方法体填 pass
```

**各片段展开结果**(实测):

```python
# class
class ClassName:
	pass

# defs(自动带 self!)
def mname(self):
	pass

# __(魔方法名)
__init__       ← 输入 __ 展开,默认 init,可改成 __str__ 等
```

**占位符顺序**:`ClassName` → `__init__` 的参数(`param`)→ 方法体;`defs` 的 `self` 不用填,自动生成,`$2` 在 self 后面补参数。

**`classi` 展开看过即撤**(完整模板,带 docstring 和 super 调用):

```python
class ClassName():
	"""docstring for ClassName."""
	def __init__(self, arg):
		super(ClassName, self).__init__()
		self.arg = arg
```

## 题 137:查看和管理片段

**操作解法**:这题全是命令,不用按键。

**① 列出 javascript 已加载的片段触发词**(实测可用):

```
:lua for _,s in pairs(require("luasnip").get_snippets("javascript")) do print(s.trigger) end
```

屏幕上会打出 209 个触发词(`function` / `for` / `co` / `desc` 等都在里面)。想先看数量:

```
:lua print(#vim.tbl_keys(require("luasnip").get_snippets("javascript")))
```

> [!note] 为什么用 `get_snippets()` 而不是 `ls.snippets`
> 本机 LuaSnip 是 2.x,`ls.snippets` 这个字段已经没了,公开 API 是 `get_snippets(文件类型)`。返回的是"片段对象"表,每个对象的 `.trigger` 字段才是触发词,所以用 `for _,s in pairs(...) do print(s.trigger)` 取。

**② `:e ~/.config/nvim/snippets/javascript.lua` 是否存在**:**不存在**——但 `:e` 会打开一个空的 lua 缓冲区,看起来像"存在"。

- 验证方法:`:w` 保存时报 `E212: Can't open file for writing`(`snippets/` 目录根本不存在);缓冲区里也只有一个空文件,没有任何片段

## 题 138:Snippet 高级技巧

**操作解法**:往题 135 的 `snippets.nix` 里追加三个片段,把下面两段插进 `extraConfigLua` 的字符串里(直接接在题 135 的 `ls.add_snippets(...)` 后面,别插到 `''` 字符串外):

```lua
-- 所有文件类型都生效:date / filename
ls.add_snippets("all", {
  ls.snippet("date", {
    ls.f(function() return os.date("%Y-%m-%d") end),
  }),
  ls.snippet("filename", {
    ls.f(function() return vim.fn.expand("%:t") end),
  }),
})
-- javascript 专属:引用占位符的 log
ls.add_snippets("javascript", {
  ls.snippet("log", {
    ls.t("console.log('"),
    ls.i(1, "variable"),
    ls.t("': "),
    ls.f(function(args) return args[1][1] end, {1}),
    ls.t(")"),
  }),
})
```

rebuild(`sudo nixos-rebuild switch --flake .#loysan`)后测试:

```
任意文件输入 date       → 当天日期(如 2026-08-06)
任意文件输入 filename    → 当前文件名(如 138-Snippet 高级技巧.txt)
js 文件里输入 log       → console.log('variable': variable),占位符填什么名字,引号里和参数里同步出现什么
```

**三个片段的核心概念 `f`(function_node)**:

| 节点 | 写法 | 求值时机 |
|---|---|---|
| `t` (text) | `ls.t("文本")` | **定义时**固定,内容写死 |
| `f` (function) | `ls.f(函数, [依赖节点])` | **展开时**调用函数,动态生成 |

- `date` / `filename`:`f(function() ... end)` 不带依赖,展开那一刻求值——所以每天、每个文件都不同
- `log` 的 `f(function(args) return args[1][1] end, {1})`:第二个参数 `{1}` 声明"依赖 1 号占位符",展开后 1 号占位符文本一变,`f` 立即重新求值,`args[1][1]` 就是 1 号占位符的当前文本——这就是"引用占位符"的实现方式

> [!warning] date 触发词会重复
> friendly-snippets 自带一整套 date 片段(`date` / `dateDMY` / `dateMDY` / `datetime` / `diso` / `time` 等,挂在 all 类型),自定义 `date` 会和它并存——输入 `date` 时菜单里会同时出现两个条目,选描述是你自己那个即可;想彻底独占可以换个触发词(如 `today`)。

## 1. FHS 标准：每个目录的职责

FHS（Filesystem Hierarchy Standard）规定 Linux 目录布局。你的系统里实际会长这样：

```
/
├── bin → /usr/bin        # 基本命令（ls cp mv...）——现在都是 symlink
├── boot/                 # 内核 + 引导文件（systemd-boot 在这）
├── dev/                  # 设备文件（/dev/sda 磁盘、/dev/null 黑洞）
├── etc/                  # 系统配置（纯文本）
│   ├── nixos/            #   传统 NixOS 配置位置（你的在 ~/nixos-config）
│   ├── passwd            #   用户列表（不是密码！）
│   └── fstab             #   磁盘挂载表
├── home/
│   └── loysan/           # 你的家目录，唯一真正属于你的地方
├── lib → /usr/lib        # 共享库（.so 文件 ≈ Windows 的 DLL）
├── nix/                  # ★ NixOS 独有，见下
├── proc/                 # 虚拟目录：进程和内核信息（cat /proc/cpuinfo 试试）
├── run/                  # 运行时数据（内存文件系统）
│   ├── current-system    # ★ 当前系统的"入口"（见下）
│   └── user/1000/        #   你的会话运行时（socket、XDG_RUNTIME_DIR）
├── sys/                  # 虚拟目录：硬件/内核参数
├── tmp/                  # 临时文件（重启清空）
├── usr/
│   ├── bin/  lib/  share/  # 软件本体、库、数据（图标/桌面文件/文档）
├── var/
│   ├── log/              # 日志（虽然 NixOS 主要用 journalctl）
│   └── lib/              # 服务数据（docker、数据库等）
└── root/                 # root 的家目录（不是你的！）
```

## 2. 你的家目录里有什么

```
~/（= /home/loysan）
├── .config/         # 应用配置（≈ %APPDATA%）—— niri、nvim、unity3d 都在这
├── .local/share/    # 应用数据（存档、插件、prefs）
├── .cache/          # 缓存（可随便删）
├── nixos-config/    # ★ 系统配置仓库（git）
├── notes/           # 这个知识库
├── Projects/        # Unity 项目
└── Unity/           # Unity Hub 装的 Editor
```

点开头 = 隐藏文件，`ls -a` 或文件管理器 `Ctrl+H` 可见。

## 3. NixOS 的特殊之处：/nix 和 /run/current-system

### /nix/store —— 一切的真相
所有软件都装在 `/nix/store/<哈希>-<包名>-<版本>/` 下：
```
/nix/store/c6mjnsxakwsg5w7ssrc7ajya13bw84sw-neovim-unwrapped-0.11.7/
/nix/store/4dp7jwjpwb9filsqnrq7x7lw3kzbzkdk-...-source/   (nixpkgs 源码)
```
哈希 = 构建输入的指纹。不同版本/不同配置的同一个包**哈希不同、互不冲突、可以共存**。
这就是 Nix 的核心，详见 [[02-Nix核心思想-纯函数式部署]]。

### /run/current-system —— 你"以为的"系统
`which nvim` 显示的 `/run/current-system/sw/bin/nvim` 其实是一串符号链接：
```
/run/current-system → /nix/store/...-nixos-system-loysan-25.11.../
    └── sw/bin/nvim → /nix/store/...-nixvim/bin/nvim → ...-neovim-0.11.7/bin/nvim
```
**你的 PATH 里并没有 /usr/bin**（它几乎是空的），
而是 `/run/current-system/sw/bin` 这个链接农场。
改配置 rebuild = 生成一个新 /nix/store 系统目录 + 把符号链接指过去 = **原子切换**。

### 为什么这很重要：/usr 不存在
传统 Linux 软件默认 `/usr/bin`、`/lib64/ld-linux-x86-64.so.2` 这些 FHS 路径。
NixOS 全都没有（除了 nix-ld 补的一个 ld.so）。
→ 从网上下载的"绿色版"二进制（Unity、各种 AppImage）直接跑会报
`No such file or directory`（明明文件在！）——说的是**加载器**不在。
解法见 [[09-运行外来二进制-nix-ld与FHS]]。

## 4. 一切皆文件（Unix 哲学实物演示）

```bash
cat /proc/cpuinfo        # CPU 信息是个"文件"
cat /proc/meminfo        # 内存也是
ls /dev/sda*             # 磁盘是文件
echo "hello" > /dev/null # 黑洞（≈ Windows 的 NUL）
```

## 5. 挂载：磁盘如何接入这棵树

```bash
df -h          # 看各分区挂载点和用量（≈ "此电脑"看磁盘）
lsblk          # 看磁盘和分区结构（树状图）
mount          # 看当前所有挂载
```
你的布局：`/` 是 ext4 主分区，`/boot` 是 EFI 分区（vfat），
外加一个 swap 分区（见 hardware-configuration.nix）。
U 盘插上自动出现在 `/run/media/loysan/`。

## 6. 常用操作对照

| 想干的事 | 命令 |
|---|---|
| 我在哪 | `pwd` |
| 这目录多大 | `du -sh 目录` |
| 磁盘还剩多少 | `df -h` |
| 找文件 | `fd 关键词`（比 find 好用，已装） |
| 找文件内容 | `rg 关键词`（ripgrep，已装） |
| 看文件类型 | `file 路径` |
| 看链接指向 | `readlink -f 路径` |

# 管道哲学与提示符

> [!info] 本页内容
> Unix 哲学如何塑造了 Linux 工具生态?管道为什么是灵魂?
> starship 这类"提示符工具"处在哪一层?

## 一、Unix 哲学:一个工具做一件事

1970s,Ken Thompson 等人的设计原则,塑造了整个 Linux 工具生态:

> 1. 让每个程序**只做好一件事**
> 2. 程序的输出要能作为另一个程序的**输入**(文本流)
> 3. 用软件组合小工具解决复杂问题,而不是写大程序

这就是为什么 `grep` 不管颜色、`sort` 不管过滤、`ls` 不管统计——**每个工具都是一个小积木**。

## 二、管道:积木的接口

```
ls -la              ← 列出所有文件
        | grep nvim ← 过滤出含 nvim 的行
        | wc -l     ← 数行数
```

| 符号 | 作用 | 例子 |
|---|---|---|
| `\|` | 管道:前一个的输出 → 后一个的输入 | `rg foo \| sort` |
| `>` | 重定向:输出写到文件 | `rg foo > result.txt` |
| `<` | 重定向:从文件读输入 | `sort < list.txt` |
| `2>` | 错误输出重定向 | `cmd 2> err.log` |
| `$( )` | 命令替换:把输出当参数 | `cd $(fd -t d \| fzf)` |
| `&&` / `\|\|` | 前成功才执行 / 前失败才执行 | `make && ./run` |

**心智模型**:Linux 命令行的所有操作 = `小工具 | 小工具 | 小工具`。这也是现代工具(fd/rg/fzf)能无缝替换经典工具(fix/grep/交互选择)的原因——**接口(文本流)没变,积木换了更好用的**。

> [!tip] 最实用的一行
> ```bash
> cd $(fd -t d | fzf)   # 模糊选择目录并进入
> ```
> 管道 + 命令替换 + fzf,三个积木组合出一个 IDE 级的"目录跳转"。

## 三、提示符的进化:从 PS1 到 starship

### 传统时代:PS1 变量
- 提示符就是 shell 的一个环境变量 `PS1`:`\u@\h:\w\$` 渲染成 `loysan@nixos:~$`
- 能写颜色、能放函数,但每换一个 shell 就要重写一遍

### starship(2019)—— 跨 shell 的提示符

**关键认知:starship 不是 shell,而是"提示符渲染器"**——它挂在任何 shell 之上:

```
shell(bash/zsh/fish) → 渲染提示符时调用 starship → 输出:
❯ loysan@loysan in ~/nixos-config on master via 🐍 v3.12 took 3s
```

| 特性 | 说明 |
|---|---|
| 跨 shell | bash/zsh/fish/nushell 同一份 `starship.toml` 配置 |
| 自动显示信息 | git 分支、Python/Node 版本、命令耗时、目录 |
| 主题生态 | 社区主题一键换 |
| 无侵入 | 不碰 shell 本身的配置逻辑 |

你的配置里 `starship` 就挂在 bash 上(`packages.nix`),`~/.config/starship.toml` 控制显示内容。

### 同类的其他选择

| 工具 | 定位 |
|---|---|
| starship | 跨 shell 提示符(最流行) |
| oh-my-posh | Windows/跨平台,主题更花 |
| pure / powerlevel10k | zsh 专属提示符 |

## 四、脚本 vs 交互:Shell 的两副面孔

同一门 bash,两个完全不同的用法:

| | 交互式 | 脚本 |
|---|---|---|
| 用途 | 敲命令、探索 | 自动化、批量 |
| 追求 | 补全、历史、提示符 | 健壮、可读、可调试 |
| 工具 | zsh/fish + starship + fzf | bash/sh + `set -euo pipefail` |
| 例子 | `ls \| rg nvim` | 部署脚本、CI 脚本 |

> [!tip] 判断标准
> 同一段命令你**手动敲第二遍**时,就该把它变成脚本或别名(`alias` / `~/.bashrc`)。
> 现代工作流里,复杂的"胶水逻辑"越来越多交给 AI 工具生成——但读懂管道、
> 会改管道,依然是 Linux 操作的地基。

# Shell 的进化:sh → bash → zsh / fish / nushell

> [!info] 本页内容
> Shell 和终端模拟器什么关系?bash 为什么是默认?
> zsh/fish/nushell 各自解决什么问题?

## 一、Shell 是什么(先归位)

终端四层结构里,Shell 在**终端模拟器之内、程序之外**:

```
终端模拟器(kitty)
  └── Shell(bash):读你输入的命令 → 执行 → 返回结果
        └── 被执行的程序(ls、nvim、git...)
```

- Shell 是"命令解释器":把 `ls -la | grep nvim` 解析成"执行 ls、管道给 grep"
- 它同时是**交互界面**(你敲命令)和**脚本语言**(写 .sh 脚本)——同一门语言两个用途

## 二、进化谱系

```
sh (Bourne shell, 1979, Unix 第七版)
└── bash (1989, GNU 项目, 1993 起 Linux 默认)
    ├── zsh (1990, 交互体验革命)
    └── fish (2005, 开箱即用派)
        └── nushell (2021, 结构化数据派)
```

### sh —— 一切的起点
- Bourne shell,随 Unix 捆绑,40 多年来所有 sh 脚本都按它的语法写
- 特性极简:没有命令行补全、没有历史、没有颜色
- 今天的意义:**脚本兼容性的底线**——`#!/bin/sh` 脚本在任何 Unix 上都能跑

### bash —— 事实标准
- GNU 对 Bourne 的增强:补全、历史(`Ctrl+r` 搜索)、`[[ ]]` 条件、数组
- 1993 年随 Linux 捆绑成为默认 shell——**Linux 生态 = bash 生态**
- 地位:服务器上 99% 的默认 shell,脚本语言里最普及的一门
- 短板:交互体验一般(补全弱、配置麻烦)、历史遗留语法(`$()` vs 反引号)

### zsh —— 交互体验革命
- 补全系统是革命性的:`cd <Tab>` 出目录补全、`git <Tab>` 出子命令补全
- **oh-my-zsh**(2009)让主题/插件一键装,引爆普及
- 向下兼容 bash 脚本,迁移成本低
- 现状:macOS 默认 shell,开发者圈第一大"高级 shell"

### fish —— 开箱即用派
- 开箱即用:语法高亮、自动建议(打字时灰色提示)、交互补全全部内置
- **语法故意不兼容 POSIX**:`if` 用 `end` 不是 `fi`——脚本不能直接跑
- 定位:交互爽,但脚本兼容性差,服务器不默认

### nushell —— 结构化数据派
- 管道里流动的不是文本而是**结构化数据**:`ls | where size > 1mb | sort-by size`
- 解决"文本管道解析地狱"(grep/awk 切来切去)
- 2021 年出现,Rust 实现,增长快但生态未成熟

## 三、对比表

| | bash | zsh | fish | nushell |
|---|---|---|---|---|
| 兼容 POSIX | ✅ | ✅ | ❌ | ❌ |
| 补全 | 基础 | 最强生态 | 内置好 | 内置 |
| 开箱即用 | ❌ | 需配 oh-my-zsh | ✅ | ✅ |
| 脚本生态 | 最广 | 兼容 bash | 自成一派 | 新 |
| 流行度 | 服务器默认 | 开发者首选 | 忠实小众 | 极客尝鲜 |
| 适合 | 一切 | 交互 + 兼容 | 交互党 | 数据处理党 |

## 四、怎么选

| 场景 | 选择 |
|---|---|
| 服务器 / 脚本 | **bash**(默认就是它,别折腾) |
| 本地交互体验 | zsh(+oh-my-zsh)或 fish |
| 大量处理结构化数据 | 试试 nushell |
| 你的现状 | bash 默认 + starship 提升提示符(见下篇) |

> [!warning] 务实建议
> Shell 是"换不换都行"的低优先级决策——你的命令、别名、配置都得跟着换,
> 而 bash 的短板(zsh/fish 的补全体验)在你用 nvim + fzf 之后**感知不到**。
> 想体验先开个 `fish` 试试,不用换默认。

# 现代终端对比:kitty / Alacritty / WezTerm / foot

> [!info] 本页内容
> 四强各有什么本事?kitty 协议为什么特别?

## 一、四强总览

| | **kitty** | **Alacritty** | **WezTerm** | **foot** |
|---|---|---|---|---|
| 语言 | Python + C | Rust | Rust | C |
| 出生 | 2016 | 2016 | 2018 | 2020 |
| 渲染 | GPU | GPU | GPU | GPU |
| 分屏/tab | ✅ 原生,强 | ❌ 无 | ✅ | ❌ 无 |
| 配置 | kitty.conf(类 INI) | YAML | Lua/JS | INI |
| 协议创新 | **kitty 协议** | 无 | 无(兼容 kitty 部分) | 无 |
| 典型用户 | nvim 玩家、平铺 WM 用户 | 极简主义者、启动速度党 | 配置党、跨平台用户 | Wayland 轻量党 |
| 你的情况 | ✅ 正在用 | — | — | — |

## 二、kitty 的独门武器:kitty 协议

标准终端和程序之间,通信靠 **50 年前的转义序列**——它能表达"移动光标、变色",但表达不了现代需求。kitty 协议是对这套老协议的扩展:

| 能力 | 传统终端 | kitty 协议 |
|---|---|---|
| 键盘 | 无法区分 `Shift+方向键` 和方向键 | **完整键盘上报**:每个键的修饰符组合都能区分 |
| 图片 | 只能显示文字 | `icat` 终端内直接显示图片 |
| 渲染 | 客户端自己画 | 远程渲染(终端把渲染工作交给客户端 GPU) |

**和 Neovim 的协同**是 kitty 生态位的关键:

- nvim 的 `tui` 对 kitty 键盘协议支持最好——`Ctrl+Shift+方向键` 这类组合在 kitty 里能正确进入 nvim
- `kitty icat` 让 nvim 插件能"在终端里看图"
- 所以 nvim 社区里,"kitty 是默认选项"几乎成共识

> [!note] 协议兼容性
> kitty 协议是**增量扩展**:老程序不认识新序列,只会忽略;kitty 照常工作。
> 这是它没有分裂生态的原因。

## 三、其他三强的定位

### Alacritty —— 极简的极限
- 设计哲学:终端只做"渲染文字"一件事,其他交给 tmux(复用器)等外部工具
- 启动最快、内存最小;也因此**没有分屏、没有 tab**——极端简约派的选择

### WezTerm —— 配置党的天花板
- Lua/JS 配置:启动动画、自定义快捷键、多域 SSH 会话都能写
- 跨平台(Windows/macOS/Linux)体验一致,`wezterm ssh` 原生支持
- 缺点:配置复杂本身成了门槛

### foot —— Wayland 原生轻量
- 只跑 Wayland(不兼容 X11),依赖最少,渲染最快之一
- 适合"什么都不要,只要快"的 Wayland 用户

## 四、怎么选(决策表)

| 你的情况 | 推荐 |
|---|---|
| 用 nvim、想要完整键盘协议 | **kitty** |
| 平铺 WM 用户,窗口管理交给 WM | **kitty**(分屏和 niri 互补)或 Alacritty |
| 只要最快最简,别的都自己装 | Alacritty |
| 跨平台、重度配置、SSH 多机 | WezTerm |
| 纯 Wayland、极简 | foot |

> [!tip] 你的组合为什么合理
> niri(平铺窗口)+ kitty(终端分屏)+ nvim(编辑器)= 三层各司其职:
> WM 管"窗口放哪",kitty 管"终端内布局",nvim 管"文本编辑"。
> 这也是 nvim/Wayland 圈的主流搭配。

## 五、不换的理由

- 终端模拟器**不影响**你的 shell 命令、配置、脚本——换终端零迁移成本
- 但换终端 = 换快捷键习惯(分屏键、粘贴键),**没有实际收益就别换**
- kitty 在当前生态位没有明显短板,继续用即可

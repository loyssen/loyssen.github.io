# 终端复用器:tmux / zellij / screen

> [!info] 本页内容
> 复用器解决什么问题?tmux 和 zellij 什么关系?
> 为什么 kitty 有分屏了还要 tmux?

## 一、解决什么问题

**场景**:你 SSH 到服务器跑一个 2 小时的构建。网络一闪断——shell 结束,任务被杀,白跑。

终端复用器把"任务"和"连接"解耦:

```
你打开的 nvim / 构建任务
        ↓ 跑在
tmux 会话(独立于连接,断开不销毁)
        ↓ 跑在
终端模拟器窗口(kitty)
        ↓ 跑在
SSH / 本地 shell
```

断线后:任务继续跑;重新连接,`tmux attach` 一键回到原样——这就是复用器的核心价值。

## 二、三家对比

| | **screen** | **tmux** | **zellij** |
|---|---|---|---|
| 出生 | 1987 | 2007 | 2021 |
| 语言 | C | C | Rust |
| 键位 | `Ctrl+a` 前缀 | `Ctrl+b` 前缀 | `Ctrl+a` + 引导菜单 |
| 配置 | 基本不用配 | `.tmux.conf`,生态成熟 | 开箱即用,插件/布局系统 |
| 会话管理 | 有 | 强(脚本化/共享) | 强(浮动窗格) |
| 现状 | 被 tmux 取代 | **事实标准** | 增长最快的现代替代 |

**核心概念(三家的共同骨架)**:

| 概念 | 说明 | tmux 示例 |
|---|---|---|
| Session(会话) | 一个独立工作区,可断开重连 | `tmux new -s work` |
| Window(窗口) | 会话内的标签页 | `Ctrl+b c` 新建 |
| Pane(窗格) | 窗口内的分屏 | `Ctrl+b %` 垂直分屏 |

## 三、tmux 上手(最常用 8 个操作)

```bash
tmux new -s work       # 新建会话 work
tmux attach -t work    # 重连会话 work(或直接 tmux a)
tmux ls                # 列出会话
tmux detach            # 会话内:Ctrl+b d 分离(任务继续跑)
```

会话内键位(`Ctrl+b` 前缀后):

| 键 | 作用 |
|---|---|
| `c` | 新窗口 |
| `n` / `p` | 下一个 / 上一个窗口 |
| `%` / `"` | 垂直 / 水平分屏 |
| `方向键` | 切换窗格 |
| `d` | 分离(回到 shell,任务继续) |
| `[` | 进入复制模式(滚屏) |

## 四、kitty 分屏 vs tmux(最常见的混淆)

| | kitty 分屏 | tmux |
|---|---|---|
| 层次 | 显示层(终端模拟器) | 会话层(shell 之外) |
| 关闭窗口后 | 任务一起死 | 任务继续,随时重连 |
| 主要场景 | 本地日常分屏 | **SSH 远程、长时间任务** |
| 键位 | `Ctrl+Shift+方向键` | `Ctrl+b` 前缀 |

> [!warning] 结论
> 本地日常:kitty 分屏足够,**不需要 tmux**。
> SSH 到服务器干活、跑长时间任务(编译/下载/训练):tmux 是刚需。
> 两者不冲突——远程 tmux 里的分屏,和本地 kitty 分屏互不干扰。

## 五、zellij:tmux 的现代替代

- **更友好的上手**:按 `Ctrl+a` 弹出引导菜单,不背键位
- **浮动窗格**:可以开一个"悬浮"小窗(类似 IDE 的快速终端)
- **布局系统**:写好的布局文件一键恢复多窗格工作区
- **插件系统**:Rust 写的插件,官方维护
- 代价:生态比 tmux 小、服务器上不一定预装

## 六、怎么选

| 场景 | 推荐 |
|---|---|
| 刚接触,本地学习 | zellij(引导菜单友好) |
| SSH 上服务器干活 | **tmux**(服务器必装,事实标准) |
| 想要脚本化工作区 | tmux(配置生态成熟) |
| 本地长期不用复用器 | 都不装(kitty 分屏够用) |

> [!tip] 学习顺序建议
> 先在本地用 tmux 练熟 8 个基本操作(5 分钟),再上服务器。
> tmux 的键位是"学一次,处处用"——zellij 的键位只在 zellij 里有效。

# 你的AI工作流:nvim 里的 AI 全家桶

> [!info] 本页内容
> 你的 nixvim 配置里配了哪些 AI 工具?
> avante、Claude 终端、Pi Agent 各自什么时候用,边界在哪。

## 一、你的 AI 使用进化(时间线)

| 阶段 | 工具 | 场景 |
|---|---|---|
| 1. 编辑器内面板 | **avante**(provider = claude) | 写代码时提问/改选中代码 |
| 2. 终端 Agent | `<leader>ac` 起 `claude` | 大任务:让它自己读仓库、改文件 |
| 3. 备用 Agent | `<leader>ap` 起 `pi` | 轻量任务/主 Agent 忙时 |
| 4. 独立 CLI | 系统终端直接跑 `claude` | 任何目录/服务器,与编辑器无关 |

## 二、全家桶一览(ai.nix)

配置在 `~/nixos-config/nixvim/plugins/ai.nix`,一条链路三个入口:

| 键位 | 命令 | 干什么 |
|---|---|---|
| `<leader>aa` | AvanteToggle | 开关 AI 面板 |
| `<leader>ae` | AvanteEdit | 对选中代码提问/修改(normal/visual 通用) |
| `<leader>ar` | AvanteRefresh | 刷新 avante 会话 |
| `<leader>ac` | `termopen("claude")` | 右侧 35% 宽终端,跑 Claude Agent |
| `<leader>ap` | `termopen("pi")` | 同样的终端,跑 Pi Agent |

## 三、avante:编辑器内的 AI(写代码时)

- 后端是 **claude**(auto_suggestions_provider 也是 claude),文件选择走 telescope
- 自动带上下文:auto_include 最多收 50 个文件(单个 ≤1MB),只看 `*.lua/*.nix/*.rs/*.ts/*.js/*.py`,排除 `node_modules/dist/.git`——**它知道你的仓库里什么算代码**
- 自动补全(auto_suggestions)是**关**的——补全时代过去了,要改直接说

典型用法:光标停住 → `<leader>aa` 问"这个函数怎么改成异步";选中一段 → `<leader>ae` 让它重写。

## 四、Claude 终端与 Pi Agent(大任务时)

`<leader>ac` 不是开个普通终端——它在当前目录直接起一个 **CLI Agent**:

```
claude "看下 nixvim 里 telescope 的配置,帮我优化"
    ↓
读文件 → 改配置 → 跑测试 → 显示 diff → 你确认
```

实现细节:右侧 35% 宽独立 buffer(`buftype=nofile`),自动进插入模式;同一个键再按一次关闭,换键自动切换。Pi Agent(`<leader>ap`)完全同构,是轻量备选。

**Claude Code CLI(你现在正在用的这个)**:系统终端里直接跑 `claude`——自主循环:你说目标,它自己读文件、搜代码、改文件、跑命令,最后给你 diff 验收。不依赖任何编辑器,SSH 到服务器也能用——这正是 2025 年 CLI Agent 流行的原因。

## 五、对比:AI 与 nvim 教程的关系

| 说法 | 事实 |
|---|---|
| "有 AI 就不用学 vim 了" | ❌ 你按 `<leader>aa` 本身就是键位;审 diff、跳转全靠 vim |
| "AI 会写,就不会有 LSP 报错" | ❌ AI 生成完,`K` 查文档、看诊断——验收环节全是 LSP 技能 |
| AI 的定位 | 打字员/初稿写手;**你才是审稿人** |

AI 承担了"想法 → 代码"的一半;另一半(看懂、审查、修)恰好是本系列的地基:键位让你在 diff 里飞、LSP 验证它没写错、fd/rg 告诉它文件在哪。

## 六、现今流行:你的配置已经在风口上

2025-2026 增长最快的形态是 CLI Agent,你的工作流(avante + Claude 终端 + CLI)正是这条路线——编辑器内小改、终端里大改,互补不冲突。

## 七、使用建议与边界

- **小步验收**:让 Agent 一次只改一件事,每次看 diff 再继续
- **给足上下文**:问题里带路径/报错,比笼统说"帮我改"强 10 倍
- **看不懂就追问**:在 avante 面板里问"为什么这么改",别让 bug 欠债
- **提交前自己过一遍 diff**——AI 写 bug 的概率不比你低
- **别杀鸡用牛刀**:改个变量名这种几秒的事,手动做

> [!tip] 一句话工作流
> 小改:自己改。中改:选中 `<leader>ae` 让 avante 改。
> 大改:`<leader>ac` 起 Claude Agent,你旁边看 diff 把关。

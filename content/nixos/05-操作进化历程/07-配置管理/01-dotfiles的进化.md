# dotfiles 的进化:手工拷贝 → 裸 git → stow/chezmoi → 声明式

> [!info] 本页内容
> Linux 的一切个人配置都藏在 `~/.` 开头的文件里:shell、编辑器、终端、git……
> 它们丢了 = 工作台重头调教。怎么备份、同步、管理这些文件,40 年演化出四代方案,
> 直到 NixOS 把"配置"这个概念整个升级(见下篇)。

## 一、dotfiles 是什么

以 `.` 开头的隐藏文件,名字来自 "dot + files",通常指 `$HOME` 下的个人配置:

| 文件 | 管什么 |
|---|---|
| `~/.bashrc` | shell 行为、别名、提示符 |
| `~/.vimrc` / `~/.config/nvim/` | 编辑器 |
| `~/.config/kitty` / `~/.gitconfig` | 终端外观、git 行为 |
| `~/.config/*` 目录 | 现代软件的统一配置目录(XDG 规范) |

刚装好的 Linux 只有默认配置;**真正"你的系统"是这些文件一点点积累出来的**——
所以它们值得像代码一样被管理。

## 二、进化时间线

| 年代 | 方案 | 核心思想 |
|---|---|---|
| 1990s | **手工拷贝备份** | 打包带走,丢了重来 |
| 2010s | **裸 git 仓库** | 让 git 直接管理配置文件本身 |
| 2012 | **GNU Stow** | 符号链接,仓库结构 = 目录布局 |
| 2018 | **chezmoi** | 模板 + 加密,多机差异化 |
| 2020s | **声明式(NixOS)** | 配置即代码,dotfiles 被吸收 |

> [!note] 统一规律
> 每代方案都在做同一件事:**把"配置管理"从手动操作变成"描述"**——
> 描述越完整,可复现性越强。从"拷文件"到"git 管文件"到"模板"再到"整机声明",一路后移。

## 三、各方案详解

### 1. 手工拷贝备份(1990s)

把 `~/.bashrc`、`~/.vimrc` 打个 tar 包扔进 U 盘/网盘,重装后手动拷回。

- 优点:零学习成本
- 痛点:备份永远过期;多台机器各自漂移;"拷贝—忘了—重写"无限循环

### 2. 裸 git 仓库(2010s)

思路转变:**不把文件复制进仓库,而是让 git 直接管理文件所在的目录**:

```bash
git init --bare $HOME/.cfg
alias config='git --git-dir=$HOME/.cfg --work-tree=$HOME'
config add .bashrc && config commit -m "update bashrc"
# 换机器:clone 后 config checkout,全部配置原样回归
```

- 优点:版本历史、回滚、远端同步(git remote)全部白送,零新工具
- 痛点:文件留在原位、改布局困难;密钥不敢进仓库;只解决"文件",不解决"包和环境"

### 3. GNU Stow(2012)

GNU 项目的老工具,2012 年前后被 dotfiles 社区重新发现。仓库按"软件"分目录,
stow 用**符号链接**把它们铺进 `$HOME`:

```
~/dotfiles/{bash,vim,nvim,git}/  →  stow  →  ~/.bashrc、~/.vimrc、~/.config/nvim/...
```

- 优点:布局清晰、`stow -D nvim` 一键撤销、仓库可单独 clone
- 痛点:没有模板(多机差异靠分支/脚本)、没有加密、内容仍是"原样拷贝"

### 4. chezmoi(2018)

把配置当作**模板 + 数据**处理:

- `.chezmoi.toml` 定义机器变量,模板语法区分机器 A / 机器 B 的差异
- `age` 加密管理密钥、token 等 secret
- 优点:多机差异和秘密文件两座大山同时解决,社区生态大
- 痛点:要学它的 DSL;仍只管文件——装包、开服务还是脚本的事

### 5. 声明式(NixOS,2020s)

配置不只是文件,而是"机器状态"本身。详见下篇——dotfiles 这个词在 NixOS 语境下变成了"配置库"。

## 四、对比表

| 维度 | 手工拷贝 | 裸 git | stow | chezmoi | NixOS 声明式 |
|---|---|---|---|---|---|
| 文件可复现 | ❌ | ✅ | ✅ | ✅ | ✅ |
| 环境可复现(包/服务) | ❌ | ❌ | ❌ | ❌ | ✅ |
| 版本历史 | ❌ | ✅ | ✅(仓库) | ✅(仓库) | ✅ |
| 模板/多机差异 | ❌ | ❌ | ❌ | ✅ | ✅ |
| 加密 | ❌ | ❌ | ❌ | ✅ | ✅(agenix) |
| 学习成本 | 零 | 低 | 低 | 中 | 高 |

## 五、现今流行(2026)

- **stow / chezmoi 仍是主流**:Arch、Hyprland 等"手动党"社区大量使用,明星 dotfiles 仓库多到看不完
- **常见组合**:chezmoi 管文件 + 一行安装脚本装包 + 符号链接收尾
- **NixOS 用户**:直接声明式,`~/nixos-config` 一个 git 仓库就是全部,不再有 dotfiles 概念
- **趋势**:dotfiles 从"备份问题"变成"环境定义问题"——关注点从"怎么复制"后移到"怎么描述"

## 六、怎么选

| 你的情况 | 选什么 |
|---|---|
| 单机、偶尔重装 | 裸 git 仓库就够 |
| 多台机器、有差异 | chezmoi(模板解决差异) |
| 喜欢 DIY、不换系统 | stow + 安装脚本 |
| 想一劳永逸 | NixOS(见下篇) |

> [!tip] 你的现状
> 你已经在进化树的终点站:`~/nixos-config` 就是你的 dotfiles——而且不止文件,
> 它连 nvim、桌面、显卡驱动、系统服务一起管了。下一讲详细拆解。
